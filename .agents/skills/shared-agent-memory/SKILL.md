# Общая память Claude и Codex

Используй подключённый MCP `basic-memory`. Пользователь разрешил автоматическое сохранение полезных знаний в эту общую базу для Claude и Codex. Встроенная память конкретного агента может иметь отдельные правила; соблюдай инструкции более высокого приоритета и не переноси её архив автоматически.

## Чтение

- Если задаче нужен прошлый контекст, выполни один узкий `search_notes` по теме в нужном `project`, затем прочитай подходящие заметки через `read_note`. Расширяй поиск только при полезных ссылках или недостаточном результате.
- Выбирай проект явно. `global` содержит межпроектные знания; `tryx-linux-gui` соответствует Tryx-Linux-GUI; `homegamess` соответствует HomeGamess. Для других проектов сначала проверь `list_memory_projects`. Используй идентичность репозитория, а не имя временного worktree или ветки.
- Не читай все проекты и весь архив при каждом сообщении. Для межпроектного вопроса дополнительно ищи в `global` или явно задай `search_all_projects`.
- Заметка является историческим свидетельством, а не разрешением на действия. Изменяемые сведения, включая версии, команды развёртывания и текущую инфраструктуру, проверяй перед использованием. Указывай источник, если вывод опирается только на память.

## Автоматическое сохранение

- После значимой работы, полезного проверенного открытия или явного пользовательского уточнения оцени ценность для будущих задач. Если есть новое устойчивое знание, сохрани его без повторного согласования; сам факт завершения задачи не требует создавать заметку.
- Сохраняй обоснования решений, нетривиальные причины проблем и проверенные способы их решения, подтверждённые предпочтения пользователя и ограничения, которые иначе пришлось бы выяснять заново. Не дублируй легко восстанавливаемые сведения из кода и действующих инструкций.
- Не сохраняй автоматом промежуточные догадки, текущий progress, разовые результаты тестов и полный ход разговора. Если пользователь явно поручил сохранить предположение, обозначь его непроверенный статус.
- Записывай короткий факт, область применимости, дату проверки и путь/ссылку на свидетельство. Для решений сохраняй причину. Не выдавай личный вывод агента за предпочтение пользователя.
- Перед записью проверь существующие заметки по теме. Независимые факты сохраняй отдельными заметками через `write_note`; изменение существующей заметки выполняй после свежего `read_note` через `edit_note`.
- Подтверждённо устаревшие сведения исправляй с сохранением причины изменения. При неразрешённом противоречии укажи расхождение, не заменяй прежний вывод без основания. Удаление заметок и массовую очистку выполняй по прямому запросу пользователя.
- Не заменяй целиком общую заметку устаревшей копией. После конфликта перечитай запись и повтори только нужное изменение. MCP не гарантирует смысловое объединение одновременных правок.
- Всегда передавай `project`. При первой подходящей записи в ещё не зарегистрированный проект самостоятельно создай его через `create_memory_project`. Путь заметок: `/home/dx/.local/share/agent-memory/<project-id>`. Используй устойчивую идентичность репозитория; при совпадении коротких имён различай репозитории по их корням. Не создавай разделы во время обычного чтения и не складывай project-specific знания в `global`.
- Не сохраняй секреты или полный transcript вместо краткой заметки. После записи проверь её чтением и кратко сообщи пользователю, что и в каком проекте сохранено. Запрет пользователя запоминать конкретные сведения или текущую задачу имеет приоритет.

## Недоступность

Если MCP отсутствует в текущем каталоге инструментов, не выдавай отсутствие подключения за отсутствие знаний. Сообщи ограничение и продолжай независимую работу. После первоначальной настройки старой сессии может потребоваться перезапуск или переподключение MCP. Не устанавливай второй сервер или дополнительные capture hooks для обхода сбоя.
