# Как ведётся работа в этом репозитории

Источник истины по процессу — `PROCESS.md` и `TASKS.md`. В удалённом GitHub действует
та же дисциплина (strict TDD), а этот файл описывает последовательность операций.

## Модель веток

- `main` — стабильная история волн. Прямые пушки запрещены (PR + CI).
- Работа волны — ветка `wave/<id>` (например, `wave/w4-fix`).
- Инфраструктурные правки (CI, `.gitignore`, процессные доки) — ветка `infra/<тема>`.
- Воркеры пишут код в своих worktree; координатор собирает ветку волны и выносит её в PR.
- Релизы — теги `vX.Y.Z` на `main`.

## Защита `main` (текущее состояние)

Серверная защита ветки (branch protection / rulesets) на free-плане GitHub для приватных
репозиториев недоступна: API отвечает 403 «Upgrade to GitHub Pro or make this repository
public». До апгрейда (или публикации репо) дисциплина «только PR + зелёный CI» держится
соглашением; в настройках репозитория уже включены squash-only merge и авто-удаление
ветки после merge. При появлении Pro включить: required PR, required check `gates`
(strict), запрет force-push и удаления `main`.

## Последовательность для каждой волны

1. **ТЗ + red-тесты** в ветке `wave/<id>` (strict TDD: сначала падающий тест, red
   фиксируется в отчёте).
2. **Локальные гейты**: `npm run gate:worker` (typecheck, meta, unit, smoke) —
   зелёный до PR.
3. **PR в `main`**: `git push -u origin wave/<id>` → Pull Request (по шаблону).
4. **CI обязателен зелёным** (job `gates`). «Пропуск прохождением не считается»:
   из skipped допустимы только задокументированные (живой Discord / CDP / браузер) —
   они перечисляются в описании PR и в warnings гейтов.
5. **Приёмка координатора**: `npm run gate:release` (e2e + coverage + golden md5),
   при необходимости — живой чек-лист (Discord/Frida).
6. **Squash-merge** в `main`, ветка удаляется автоматически.
7. **Релиз**: тег `vX.Y.Z` на `main` (`git tag`, `git push origin vX.Y.Z`).

## Правила

- `golden`-каталоги (`functions/`, `logs/`, `evidence/`, `.gate/`) не коммитятся,
  не изменяются и не удаляются; их целостность проверяет `gate:release`.
- Изменения в проекте ведутся только с покрытием: новый код — новый тест.
- Секреты, токены, персональные данные в репозиторий не попадают.
- История — линейная: только squash-merge, без merge-коммитов.
