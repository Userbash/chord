## 4. Семантика кода vs ТЗ (пп.1–8)

Пункты ТЗ 1–8 выполнены (`gateway.rs` прочитан целиком; тесты — только публичный API):
1) op10 → интервал из `d.heartbeat_interval` (из провода, не из константы — верно), первый удар
`now + seed % interval`, повторный HELLO до удара пере-планирует / после — игнорируется;
2) `on_timer`: мёртв → пусто; зомби при `now ≥ pending + interval` (saturating), приоритет над
ударом; иначе удар при `now ≥ next_due` с `d = last_seq` (до диспатча `None`); 3) ACK с
`pending`: `rtt = now − sent`, `next_due = now + interval`, `pending = None`; «лишний» ACK
игнорируется; 4) op0: `s` int → `last_seq`; 5) op7/op9 → `Reconnect{ServerRequest/InvalidSession}`,
сессия мертва; 6) op1/op2/40/999/-1/i64::MAX и ~100 мусорных термов — без эффектов, мусор →
`Decode`; 7) `next_deadline_ms = min(удар, зомби)`/`None`; 8) `unsafe` запрещён линтом
`[lints.rust] unsafe_code = "forbid"` (в `crates/discord-core/Cargo.toml`), кода `unsafe` нет.
`std::time` в модуле не используется (grep — чисто, только упоминание в докстроке).
`unwrap/expect/panic!` в продовом коде модуля отсутствуют (grep — только asserts в
`#[cfg(test)]`); арифметика времени — saturating.

**Мои дополнительные крайние тесты** (6/6 passed, файл только в копии
`review/mut/crates/discord-core/tests/review_extra.rs`, в репозиторий не вносился) подтвердили
