# W11a — rate-limit/ошибки (P1-09 / T-REST-05/06)

- **сделано:** реализованы чистые функции `rate_limit_info`, `classify_failure`,
  `retry_delay`, `should_retry` в `rust/crates/discord-core/src/rest/rate_limit.rs`:
  регистронезависимый поиск заголовков (`retry-after`, `x-ratelimit-*`), разбор целых/дробных
  секунд через `Duration::try_from_secs_f64` (битые/отрицательные/NaN/∞ → `None`), приоритет
  `retry-after` → тело `retry_after` → `x-ratelimit-reset-after`, минимальный JSON-сканер полей
  `retry_after`/`global` (строковые значения и escape `\"` пропускаются), классификация
  429/401/5xx/4xx, экспоненциальный бэкофф с saturating-арифметикой (`u32::MAX` не переполняет),
  политика повторов по идемпотентности методов (RFC 9110 §9.2.2). Новых зависимостей нет.
  Покрытие кейсов ТЗ §1: 1) `retry-after: 1` → 1 с, `global=false`; 2) тело `0.25`+`global:true`
  → 250 мс; 3) заголовок `2` главнее тела `0.5`; 4) fallback `reset-after: 1.5` + `remaining: 4`
  + `bucket: abc`; 5) `abc`/`-1`/`NaN`/`inf`/`1e999` → 0 без паник, ключ в строке сообщения
  не считается полем; 6) 200/204/302 → `None`, 401 → `Unauthorized`, 404 → `Client`,
  500/503 → `Server`, 429 → `RateLimited`; 7) 429 cap по `max`, 5xx `base/2base/4base`,
  `attempt=u32::MAX` → `max`, 401/4xx → `None`; 8) 429 — все методы, 5xx — GET/PUT/DELETE,
  не POST/PATCH; 401/404 — никогда.
