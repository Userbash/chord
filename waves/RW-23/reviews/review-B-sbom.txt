**Findings**

- **P1 — [scripts/sbom.mjs](/home/sanya/orca/project/scripts/sbom.mjs:48): SBOM не включает locked-зависимости.** `cargo metadata` вызывается без `--no-deps`, но именно этот флаг нужен, чтобы оставить в выводе только workspace packages. `Cargo.lock` затем используется лишь для хеша namespace; зависимости из lock и их локальные `Cargo.toml` не добавляются. Это противоречит контракту P8-04, который требует workspace **и** locked dependencies, и означает, что SBOM и `--check` не покрывают лицензии сторонних crates. Минимальная проверка: `cargo metadata --offline --no-deps --format-version 1 --manifest-path rust/Cargo.toml` — сравнить `packages` с записями в `rust/Cargo.lock`. Ожидается, что SBOM содержит и locked dependencies, а `--check` проверяет их лицензии. Тест дополнительно ожидает `packages.length >= 60` ([sbom_contract.rs](/home/sanya/orca/project/rust/crates/discord-conformance/tests/sbom_contract.rs:66)), хотя в workspace сейчас 11 crate-манифестов; при `--no-deps` это ожидание не соответствует формату вывода.

- **P1 — [scripts/sbom.mjs](/home/sanya/orca/project/scripts/sbom.mjs:80): parser игнорирует недопустимые символы в выражении лицензии.** Регулярное выражение извлекает только допустимые на вид токены, не проверяя, что они покрывают всю строку. Поэтому `MIT !!!` токенизируется как `MIT` и проходит allowlist; `GPL-3.0-only !!! OR MIT` также может пройти как `GPL-3.0-only OR MIT`. Это позволяет некорректной записи обойти проверку лицензий. Команда для воспроизведения: `node scripts/sbom.mjs --check-license 'MIT !!!'`. Ожидается exit 1 для синтаксически недопустимого выражения; текущий parser возвращает успех.

- **P2 — [scripts/sbom.mjs](/home/sanya/orca/project/scripts/sbom.mjs:12): allowlist шире замороженного контракта.** В него добавлены `CDLA-Permissive-2.0` и `LLVM-exception`; последний разрешён и как самостоятельный атом. Контракт перечисляет фиксированный набор лицензий и отдельно называет `LLVM-exception` только как exception в `WITH` ([WAVE-PLAN.md](/home/sanya/orca/project/waves/RW-23/WAVE-PLAN.md:54)). Это может пропустить лицензию, которую владелец не включал в allowlist. Проверка: `node scripts/sbom.mjs --check-license CDLA-Permissive-2.0`; ожидаемый по контракту результат — exit 1.

- **P2 — [scripts/release.sh](/home/sanya/orca/project/scripts/release.sh:62): сравнение source и destination зависит от написания пути.** Проверка same-file срабатывает только при точном совпадении строк. Например, `bash scripts/release.sh --output rust/./dist` задаёт каталог, совпадающий с `rust/dist`, но отличается от `$RUST_DIR/dist` строкой. Если SBOM уже существует, `install` может завершиться ошибкой «same file». Ожидается нормализовать пути или сравнить реальные файлы и успешно сформировать checksums при любом эквивалентном пути. Это статический вывод; команду сборки/release я не запускал.

- **P2 — [rust/crates/discord-conformance/tests/sbom_contract.rs](/home/sanya/orca/project/rust/crates/discord-conformance/tests/sbom_contract.rs:118): тесты не проверяют фактический release-path и содержимое отношений SBOM.** Проверяется `ci.sh --dry-run` и наличие строки в исходнике, но CI-hook фактически не запускается; для release проверяется только dry-run. Для SBOM проверяется, что `relationships` не пуст, без проверки `DESCRIBES` для workspace-пакетов или `DEPENDS_ON` для зависимостей. Поэтому эти тесты не ловят сбой установки артефакта и отсутствие dependency relationships. Ожидаются проверки реального вызова SBOM в безопасном временном окружении и конкретных package/relationship-инвариантов.

**Проверки без finding’а**

- Операторы `AND`/`OR`, скобки, `WITH` и остаток распознанных токенов обрабатываются parser’ом с приоритетом `AND` над `OR`; тест покрывает несколько комбинаций, но не недопустимые символы.
- `cargo metadata` запускается с `--offline` и фильтром host target; команды передаются через `execFileSync` как аргументы, без shell-интерпретации.
- `rustc -vV` fallback при любой ошибке — намеренное best-effort поведение для известных платформ; для неизвестной пары OS/architecture выдаётся ошибка. EPERM-ветка Cargo принимает только status 0 со stdout и затем парсит JSON.
- `NOASSERTION` допустим в генерируемом SPDX, а `--check` его отклоняет как неизвестную лицензию. В workspace-пакетах тест требует отсутствие `NOASSERTION`, но реальное поведение при недостающей лицензии отдельно не проверено.
- SPDX JSON содержит версию 2.3, стабильный `SOURCE_DATE_EPOCH` по умолчанию и namespace по хешу lockfile. Тест не сравнивает два документа для воспроизводимости; сортировка использует `localeCompare`, поэтому независимость порядка от locale/runtime не доказана.

**Итог:** P0: 0, P1: 2, P2: 3. **Вердикт: не принимать до исправления двух P1** — сейчас SBOM не охватывает locked dependencies, а parser способен пропускать некорректные выражения лицензий. Никакие файлы не изменялись; команды и тесты не запускались.
