# ТЗ RW-14 — P2-06 «История сообщений в памяти и пагинация»

## 1. Цель

Добавить в `discord-core` memory-only историю сообщений: ограниченное окно на канал,
слияние live-событий и типизированных страниц, пагинацию `latest`/`before`/`after`/`around`,
generation-токены и селекторы. Без REST-JSON, сети, SQLite, UI, отмены/таймаутов и новых
зависимостей.

DoD этой волны: T-DATA-08 на fake-страницах (в памяти), T-REST-08 — только request-формы;
response/`has_more`/max limit/`after` остаются за `MessagePage`/адаптером (см. RESEARCH §3).

## 2. Замороженный контракт

См. `DESIGN-P2-06.md` §1–§8. Публичные имена:

- `discord_core::history::{History, HistoryConfig, HistoryDiagnostics, HistoryError}`;
- `discord_core::history::{Cursor, PageRequest, MessagePage, PageToken, PageApply, PageError}`;
- `discord_core::history::LiveOutcome`;
- `History::{new, config, diagnostics, apply_live, begin_page, apply_page}`;
- селекторы §6.

`Effect::FetchMessages` и `state::Message` не меняются.

## 3. Воркеры и файлы

### W14a — окно/типы

Файлы:
- `rust/crates/discord-core/src/history/types.rs`
- `rust/crates/discord-core/tests/history_types.rs`

Содержание: `HistoryConfig`, `History`, `ChannelHistory`, `WindowDirection`,
`HistoryDiagnostics`, `HistoryError`, `LiveOutcome`; `new`/`Default`/`config`/`diagnostics`/
`apply_live`, примитивы `ensure_channel`, `insert`, `trim`, `iter` (`pub(crate)` для W14b/c).

Кейсы (red-first):

1. `HistoryConfig::default`: window 100, page 50; `new` с `channel_window=0` → `ZeroWindow`,
   `page_limit=0` → `ZeroPageLimit`; `History::default()` пуст и валиден.
2. Три реальных `023/024/025` через `State`/reducer → id возрастают, content 208/168/173,
   author `268478587651358721` bot, guild `1014537851418980372`; неизвестный канал пуст.
3. Повторная вставка id `v1`→`v2`: len 1, content `v2`; live-replace не считается duplicate.
4. `023` + `026` через reducer → history upsert полного `Message`: len 1, embed 1, content 208.
5. cap=3: Latest ids `[1,2,3,4]` → `[2,3,4]`; Before `[1,2,3,4]` после cursor Before →
   `[1,2,3]`; два канала независимы; `evicted` считается.
6. Live в detached `Before`/`Around` с id > newest → `Deferred`, `has_newer=Some(true)`,
   старые не вытеснены.

### W14b — пагинация/слияние

Файлы:
- `rust/crates/discord-core/src/history/pagination.rs`
- `rust/crates/discord-core/tests/history_pagination.rs`

Содержание: `Cursor`, `PageRequest`, `MessagePage`, `PageToken`, `PageApply`, `PageError`;
`from_effect`, `query`, `validate`, `begin_page`, `apply_page`; dedup/last-wins, Live > Page,
атомарный `ChannelMismatch`, stale token.

Кейсы (red-first):

1. `from_effect(FetchMessages{before:None,limit:12})` → Latest/`limit=12`;
   `Some(id),24` → Before/`before=id&limit=24`; прямой Around(30) → `limit=30&around=id`;
   After(20) → `after=id&limit=20`; другой эффект → None; 0/too-large → ошибки.
2. Before-страница `[3,1,2]` → `[1,2,3]`; `has_older=Some(false)` сохраняется; чужой
   `channel_id` → `ChannelMismatch`, окно не изменилось.
3. After `[4,5]` → `[1..5]`; cap=4 → `[2,3,4,5]`; Around anchor 4 `[2,3,4,5,6]` cap=4 →
   `[2,3,4,5]` (tie оставляет меньший id); пустая страница не меняет сообщения.
4. page id2 `old` → live id2 `edited` → stale page id2 `old`: остаётся `edited`;
   page/page last-wins; live create в Latest вытесняет oldest; live в detached Older
   поднимает `has_newer`.
5. Пустая страница с валидным токеном → Ok; короткая страница `has_older=None` не затирает
   известное `Some`; повтор страницы не растит len, duplicates считаются.
6. token1/token2: apply token1 → `StaleToken`, без изменений; token2 → Ok; чужой канал
   в токене/странице → отказ; без паник.

### W14c — селекторы

Файлы:
- `rust/crates/discord-core/src/history/selectors.rs`
- `rust/crates/discord-core/tests/history_selectors.rs`

Содержание: `History`-селекторы §6: `messages`, `recent`, `message`, `oldest/newest`,
`has_older/newer`, `range`, `window_around`, `len`/`is_empty`/`channel_count`/`total_len`.

Кейсы (red-first):

1. Два канала: `messages` — ascending только своего канала; `message`; неизвестный канал пуст;
   cross-channel не протекает.
2. Границы `None` остаются `None`; `Some(false)/Some(true)` сохраняются; `None` не становится
   `false`.
3. `recent(3)` — newest-first; `oldest/newest`; `range` включительно; `from > to` пуст;
   `limit=0` пуст.
4. `window_around(anchor)` — ближайшие, tie детерминирован (меньший id), результат ascending;
   anchor отсутствует — ближайшие; вызовы не мутируют.
5. Детерминизм: две одинаковые истории, повтор селектора; `Default` пуст; `Debug` History
   не печатает content.
