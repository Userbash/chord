# ТЗ RW-13 — P2-02 «Модель состояния и чистый reducer»

## 1. Цель

Добавить в `discord-core` детерминированную модель состояния Discord и чистый reducer
`(State, Event) -> (State, Effects)` поверх принятой READY-модели P2-01. Без I/O, SQLite,
UI, сети и новых зависимостей.

DoD карточки P2-02: reducer; слияние READY/READY_SUPPLEMENTAL/RESUMED; индексы; эффекты-
декларации; детерминизм по фикстурам; T-DATA-04.

## 2. Замороженный контракт

См. `DESIGN-P2-02.md` §1–§10. Публичные имена:

- `discord_core::state::{State, Event, EventPayload, EventError, StateDiagnostics}`
- `discord_core::state::{apply, apply_dispatch, apply_frame}`
- `discord_core::state::{Effect, Effects, MemberRange}`
- `discord_core::state::{Message, MessagePatch, Thread, ThreadListSync, ChannelInfo,
  ReadySupplemental}`
- `State::from_ready`, селекторы из DESIGN §8.

README/доки не меняются этим ТЗ (координатор обновит после приёмки).

## 3. Воркеры и файлы

### W13a — типы и разбор событий

Файлы (только эти):
- `rust/crates/discord-core/src/state/types.rs`
- `rust/crates/discord-core/tests/state_types.rs`

Содержание: `State`, `StateDiagnostics`, `Event`, `EventPayload`, `EventError`, `Message`,
`MessagePatch`, `Thread`, `ThreadListSync`, `ChannelInfo`, `ReadySupplemental`, `Effect`,
`Effects`, `MemberRange`; `State::from_ready`; `Event::from_frame`/`from_routed`;
разбор перечисленных событий; `Debug` с redaction.

Кейсы (red-first):
1. READY: `Event::from_frame` на `002-READY.json`, `s=1`, payload Ready.
2. READY_SUPPLEMENTAL: 7 групп; сырые `[17,14,7,2,10,87,1]` (138), после P2-01 dedup
   `[16,14,7,2,10,87,1]` (137); первый id.
3. SESSIONS_REPLACE: массив, 1 сессия, status `invisible`, client desktop/linux.
4. THREAD_LIST_SYNC: реальная фикстура с отрицательным `guild_id` → `InvalidId`; синтетика
   с теми же полями и валидными id → `thread_metadata`/счётчики.
5. CHANNEL_INFO: синтетика с 1 каналом; поля из READY-оракула; реальные 75 отрицательных
   id → `malformed`-диагностика.
6. MESSAGE_CREATE: content length 208, author bot, id/channel/guild, timestamp.
7. MESSAGE_UPDATE: `content` 208 символов (не пустой), `embed_count=Some(1)`, тот же id.
8. Неизвестный `t` → `Unknown`, не ошибка; известный не-поддержанный → `Unsupported`.
9. MESSAGE_CREATE без `channel_id` → `Missing("message.channel_id")`.
10. SESSIONS_REPLACE с объектом вместо массива → `WrongType`.
11. `State::Debug` не содержит `session_id`/`user_settings_proto`.
12. Битые элементы supplemental → `malformed`, не паника.

### W13b — reducer

Файлы (только эти):
- `rust/crates/discord-core/src/state/reducer.rs`
- `rust/crates/discord-core/tests/state_reducer.rs`

Содержание: `apply`, `apply_dispatch`, `apply_frame`, слияние всех событий, stale-политика,
эффекты, диагностика, upsert-ы.

Кейсы (red-first):
1. `State::from_ready` на реальном READY: 7/272/17/146/60/157/58/1, self user, индексы.
2. Два одинаковых прогона READY → равные state/effects; 7 `SubscribeMembers` по возрастанию
   guild_id.
3. READY + SUPPLEMENTAL: members `[16,14,7,2,10,87,1]` (137 после dedup), первый nick,
   `last_seq=2`.
4. READY + SESSIONS_REPLACE: 1 сессия, status `invisible`.
5. THREAD_LIST_SYNC: upsert и повторное обновление без дублей.
6. CHANNEL_INFO: upsert канала и заглушка неизвестной гильдии.
7. READY + MESSAGE_CREATE + MESSAGE_UPDATE: 1 сообщение, content `""`, embeds=1, author в
   `users`.
8. Stale `s` игнорируется, данные не меняются, `stale_sequences`.
9. READY с `s=1` после `last_seq=21` сбрасывает состояние и не считается stale.
10. Unknown/Unsupported: диагностика, данные не меняются, `last_seq` обновляется.
11. Malformed dispatch: диагностика, без паники, данные не меняются.
12. MESSAGE_UPDATE неизвестного сообщения с `channel_id` → заготовка + `inconsistencies`;
    без `channel_id` → `malformed`.
13. `Effect`-варианты и `Effects` API компилируются (интерфейс для следующих карточек).
