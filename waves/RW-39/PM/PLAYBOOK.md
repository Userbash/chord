## 4. Экономия токенов (обязательно для всех ролей)

- **Контекст-пак вместо доков**: PM выдаёт ≤ 1 страницу брифа + точные `sed -n`/`grep`
  диапазоны. Полные `PROCESS/TASKS/STATE` воркер не читает.
- **Греп вместо Read**: `rg -n`, `sed -n 'a,bp'`, `head`, `wc -l`. Читать файл целиком —
  только если < 200 строк.
- **Артефактный хендофф**: результат = файл-артефакт + 5–10 строк сводки, а не пересказ кода.
- **Один источник чисел**: дизайн-значения только из `DESIGN/tokens.css` (не дублировать в чат).
- **Без пересказов логов**: в отчёт — команда + вердикт + путь к логу, не тело лога.
- **Память сессии**: `PROJECT-CONTEXT.md` + `PM/LOOP-LEDGER.md` + `waves/RW-39/PM/STAGE.md`;
  новый диалог стартует с них, а не с истории волн.

## 5. Защита от зацикливания (anti-loop)

### 5.1 Детектор

Петля = **одинаковая сигнатура отказа** на двух итерациях подряд:

```
sig = sha1(<finding-id> | <scope-files> | <failing-command> | <первая строка ошибки>)
```

PM считает `sig` при каждом возврате. Совпадение с прошлой итерацией = `LOOP-DETECTED`.
Дополнительные триггеры: 3 возврата по одной карточке; автор и ревьюер дают
противоречивые требования; «зелёный» тест при явно невыполненном DoD.

### 5.2 Лестница выхода (обязательна, по порядку)

| Шаг | Действие | Кто |
|---|---|---|
| 0 | Зафиксировать сигнатуру, гипотезу и **минимальный repro** в ledger | PM |
| 1 | Переформулировать приёмку как **исполняемую проверку** (тест/команда), а не прозу | PM + REV |
| 2 | **Сменить подход**, а не повторять: другой механизм (X11 vs AT-SPI), другой контракт (ADR), другой инструмент (REA/SocratiCode↔rg) | PM |
| 3 | Сузить/разбить карточку, явно вынести вне scope (с владельцем и сроком) | PM |
| 4 | Эскалация владельцу: «принять как известное ограничение» **только** письменно, с риском | PM → владелец |

Запрещено: третий идентичный заход, «зеленить» тест, тихий skip, расширение scope без записи.

## 7. Run budget (введено после разбора: окно открывалось ~19 раз за 50 минут)

Причина была не в тестах, а в брифе PM: список команд без бюджета + полный gate у воркера.

| Правило | Значение |
|---|---|
| GUI-команды на воркера (`probe`, `launch`, smoke) | **≤ 2** (1 red + 1 green); 3-й запуск — только с разрешения PM |
| Полный `npm run gate:worker` | **только PM**, один раз на batch; воркеру запрещён |
| Одинаковая команда с тем же результатом | не повторяется; результат берётся из лога |
| Каждый GUI-прогон в отчёте | строкой `команда → зачем → exit code` |
| Флейк-ретрай | 1, с записью обоих результатов; больше — сигнал, а не повтор |

Следствие для брифа: поля **RUN BUDGET** и **STOP RULE** обязательны (см. §3).
Цена гейта уже видна в `.gate/*.json` (`phases[].ms`), отдельная карточка не нужна:
`node -e "const j=require('./.gate/<file>.json'); console.log(j.phases.map(p=>p.name+' '+p.ms+'ms').join('\n'))"`.
Замер 2026-10-23T16:11: `smoke 17 153 мс` из `17 648 мс` — **97 % гейта это живое окно**,
остальные стадии 0,44 с. Поэтому `gate:worker` — только на приёмку (WINDOW-BUDGET).

Исполнение (2026-10-23): `WINDOW-BUDGET.md` — кэш по ключу UI+бинаря
(`window-budget.mjs`); `loop-guard.mjs` — жёсткий лимит попыток (3-я только со сменой подхода).
Итерации — DOM/model/geometry без окна (47/47, ~120 мс), gate — один раз на приёмку.

## 8. Протокол общения PM ↔ воркер

PM пишет только то, что можно проверить командой. Формулировки «поправь качество»,
«сделай красиво», «посмотри внимательно» запрещены — они и создают петлю.

| Событие | Формат | Обязательные поля |
|---|---|---|
| Постановка (BRIEF) | файл `PM/BRIEF-<id>.md` | файлы-владельцы, 2–4 источника, RED-команда, GREEN-критерий, run budget, запреты, путь отчёта |
| Возврат (RETURN) | запись в `LOOP-LEDGER` + сообщение воркеру | `finding`, `repro` (точная команда), `expected`, `actual`, `scope` (файлы), номер итерации |
| Приёмка (ACCEPT) | запись в `DECISIONS.md` + `STAGE.md` | что проверено PM лично (команда/вывод), md5, остаток |
| Эскалация | `LOOP-LEDGER` §Эскалация | 2 одинаковые сигнатуры; варианты: принять ограничение / отдельная волна / ADR |

Возврат без `repro` не принимается к исполнению: сначала PM/ревьюер дают команду,
воспроизводящую дефект. Воркер с RETURN не меняет тесты и не расширяет scope — только
указанные файлы; спор решается через PM, а не правкой чужих файлов. Проверка «не ослабил
тесты»: `git diff -- tests/` + чтение untracked-тестов; удалённый `assert`/`skip` без записи
в отчёте = P0, работа возвращается целиком.
