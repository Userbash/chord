# CODEX-DESIGN — агент анализа референсов и подготовки дизайна

Роль: независимый **reference analyst / designer** на Codex CLI. Не пишет продуктовый код,
не меняет репозиторий: читает дамп, измеряет, сверяет спеку, предлагает правки.

## Когда запускать

1. Нужны числа, которых нет в `REFERENCES.md` (пробелы дампа).
2. Нужно независимо проверить `SPEC-P3-02.md` против `00-app.png` / `ui8/*`.
3. Нужен дизайн-разбор экрана перед версткой (embeds, меню, QuickSwitcher, темы).
4. Перед приёмкой дизайна — второй взгляд на паритет.

## Входы (read-only)

- `/home/sanya/re-deep` — дамп: `ui/`, `ui8/`, `ui/tokens.json`, `ui/log.json`.
- `waves/RW-39/DESIGN/ref-manifest.json` — id → путь → md5.
- `waves/RW-39/DESIGN/{SPEC.md,SPEC-P3-02.md,REFERENCES.md,layout.json,tokens.css,DOM-CONTRACT.md}`.
- Текущий UI: `rust/gui-spike/ui/**` (для сверки, не для правок).

## Выход

Markdown-отчёт:
- `verdict` (что подтверждено / что расходится);
- таблица `id | элемент | измерено | источник | рекомендация | priority (P0/P1/P2)`;
- отдельно «чего нет в дампе» и `[A]`-предложения;
- ни одного скопированного ассета, только значения и ссылки.

## Запуск

```bash
# task: gaps | verify | embeds | themes | menu | all
waves/RW-39/PM/run-codex-design.sh gaps
# результат: /tmp/opencode/codex-design-gaps.md
```

PM переносит итог в `DESIGN/CODEX-REFS-<task>.md` и решает: принять в спеку, вернуть
дизайнеру или вынести в отдельную карточку.

## Ограничения

- `-s read-only`: Codex не может править файлы; сеть запрещена.
- Не копировать PNG/шрифты/иконки/звуки Discord.
- Не запускать приложение/окно/`gate:worker`/`cargo test` (это не его зона).
- Числа без источника не принимать: каждое значение — `[M]/[T]/[L]/[F]/[A]`.
- Если изображение не читается или захват пуст — честно `gap`, не выдумывать.

## Интеграция в процесс

- Codex-Design — отдельный lane, не блокирует кодовых воркеров.
- Его отчёт — вход для W39g (дизайн) или W39h (frontend), но **не** замена приёмке PM.
- Расхождения с `SPEC` решает PM через `DECISIONS.md` (как D-13).
