# RW-39 / DESIGN — как читать и как воспроизвести замеры

Артефакты Phase 1a (RE) волны RW-39. Владелец документов: W39b (`SPEC.md`, `tokens.css`,
`DOM-CONTRACT.md`); машиночитаемые выжимки и замеры: W39a.

| Файл | Что внутри | Источник истины для |
|---|---|---|
| `SPEC.md` | числа и правила: цвета, типографика, сетка, компоненты, экраны | всех решений вёрстки (W39c) |
| `tokens.css` | единственный источник **значений** (205 токенов + 3 блока оверрайдов / 6 деклараций) | `ui/components/tokens.css` |
| `DOM-CONTRACT.md` | канонический `ui/index.html`, id/классы/ARIA, инварианты RW-38 | разметки (W39c/W39d) |
| `tokens.json` | те же 205 токенов машиночитаемо: значение + статус + ссылка на дамп | сверки/генерации, аудита |
| `layout.json` | геометрия shell и 4 экранов, schema `rw39/layout-v1`, `source` у каждого блока; `regions`, `screens.*.measured`, `discrepancies[]` | проверки размеров |
| `REFERENCES.md` | таблица референсов: что и чем измерено, коды `[M]/[T]/[L]/[A]/[F]`, пробелы дампа | провенанса чисел |
| `README.md` | этот файл: воспроизведение, юр. рамка | — |

Скрипты и логи замеров: `waves/RW-39/PM/w39a/` (`measure.py`, `measure.json`,
`gen-tokens.mjs`, `verify-tokens.mjs`, `verify-layout.mjs`, `REPORT.md`).

## 1. Правила чисел

1. Любое число в `SPEC.md` имеет код: `[M]` измерено, `[T]` токен дампа, `[L]` RE-контракт
   RW-37, `[A]` assumption, `[F]` заморожено тестами RW-38. Нет кода — числа нет.
2. Единицы — **CSS px**. Референс снят при `dpr 1.25`: PNG 2560×1383 ↔ окно 2048×1106.4,
   поэтому `css = px_png / 1.25`.
3. `tokens.json` обязан совпадать с `tokens.css` **1:1** (имена и значения посимвольно).
   Расхождение — ошибка сборки артефактов, а не «мелкая правка».
4. `layout.json` не вводит новых чисел контракта: он собирает уже принятые (`SPEC`/`tokens.css`/RW-37)
   и помечает источник каждого блока. RE-детализация (`regions`, `screens.*.measured`) описывает
   те же размеры с точками замера; расхождения со SPEC — только массив `discrepancies[]`
   (решение принимает PM, файлы W39b не правятся).
5. После D-02 (палитра из дампа: `--danger #da3e44`, `--positive #3d9e60`,
   `--warning #fdb833` и др.) и D-04 (высоты строк 26 / 48 / +22, участник 42)
   `tokens.css` = **205 токенов** (добавлены `--row-h-continuation`, `--row-h-group-start`,
   `--row-line-extra`, `--row-h-member`, `--row-channel-pitch`), md5
   `7ce9c1f03e26056243e13df3237b0a9d`; `tokens.json` перегенерирован владельцем, расхождений
   с дампом — 0. Число токенов и md5 меняются только владельцем `tokens.css` — при
   расхождении ориентируйтесь на вывод `verify-tokens.mjs`.

## 2. Воспроизведение замеров

Всё выполняется из корня репозитория. Референсы — `reference-oracle/` (read-only).

```bash
# 2.1 Пиксельные замеры (PNG lossless + JPEG-кроп панели участников + DOM rect'ы)
python3 waves/RW-39/PM/w39a/measure.py            # таблица в stdout
python3 waves/RW-39/PM/w39a/measure.py --json     # + measure.json (числа для layout.json)

# 2.2 Токены: генерация и проверка 1:1 с tokens.css
node waves/RW-39/PM/w39a/gen-tokens.mjs           # перезаписать tokens.json
node waves/RW-39/PM/w39a/gen-tokens.mjs --check   # 0 = tokens.json актуален, 1 = рассинхрон
node waves/RW-39/PM/w39a/verify-tokens.mjs        # имена/значения/md5/оверрайды + сверка с дампом

# 2.3 Геометрия: диапазоны ТЗ, source у блоков, ссылки на токены
node waves/RW-39/PM/w39a/verify-layout.mjs

# 2.4 JSON обязан парситься (обязательный минимум приёмки)
node -e "for (const f of ['tokens.json','layout.json']) JSON.parse(require('fs').readFileSync('waves/RW-39/DESIGN/'+f));"
rg -n "rail|tree|header|composer|members" waves/RW-39/DESIGN/layout.json | head
```

Ожидаемые строки (актуально на 2026-10-24, после D-02/D-04):

```
ok: 205 токенов 1:1 с tokens.css (md5 7ce9c1f03e26056243e13df3237b0a9d); dump_refs: 57 match, 0 mismatch, 0 missing
ok: layout.json — 65 блоков с source, 22 ссылок на токены, экранов 4; rail 64, tree 240/311, header 49, composer 56, members 240/256, rows 26/48 + member 42; колонки 2047.8 ≈ 2048
```

Если `gen-tokens.mjs --check` падает — `tokens.css` изменился, а `tokens.json` нет:
перегенерируйте и проверьте, что расхождения с SPEC (§6) согласованы с W39b/PM.

## 3. Чем именно мерено (методы)

| Что | Как | Точность |
|---|---|---|
| Границы панелей, полосы, боксы | PIL: скан строки/столбца PNG, поиск смены цвета; composer — столбцы, закрашенные `(34,35,39)` на ≥80 % высоты | ±0.8 CSS (1 px PNG) |
| Высоты строк каналов | медиана шага текстовых полос дерева (n=19) + высота выделенной строки | ±0.8 CSS |
| Шаг строки участника | `ui8/22-members.jpg`: профиль «верхушки аватаров» по x 8…52, медиана шагов (n=16) | ±1 CSS (JPEG) |
| Панель/модалка/поля | `getBoundingClientRect` из `ui8/*.json` (CSS px, без пересчёта) | ±0 (число драйвера) |
| Токены | `ui/tokens.json` → нормализация `hsl()`/`color-mix()`/`calc()` и сравнение с `tokens.css` | точное сравнение |
| Цвета | точечные пробы lossless PNG, частотный скан насыщенных пикселей для статус-точек | ±0 (PNG) |

Ограничения: hover/focus/active в статике не сняты; JPEG-кроп панели участников даёт ±1 px;
ширина рейла не видна пиксельно (рейл и дерево одного цвета `#121214`) и подтверждена
rect'ом кнопки гильдии + токеном.

## 4. Юридическая рамка

1. Проект неофициальный. Бренд в UI — **`DL`** (монограмма в рейле). Названия и логотипы
   Discord, «Nitro», «Boost» не используются.
2. Из референсов переносятся **только значения** — цвета, размеры, отступы, высоты строк.
   PNG/JPG, шрифты, иконки, спрайты, аватары, эмодзи-картинки **не копируются** в репозиторий.
3. Шрифты — только системные (`system-ui` + системный emoji-стек), без `@font-face` и `url()`.
4. Иконки — собственные inline-SVG 24×24 (`stroke="currentColor"`, `stroke-width="2"`),
   сторонние наборы не подключаются.
5. Сеть в UI не используется; экраны работают на `fixtures/` (W39e) или локальных данных.
6. `reference-oracle/` — golden: только чтение, файлы не изменяются и не переименовываются.

## 6. Чего здесь нет

Полный список пробелов дампа — `REFERENCES.md` §7. Кратко: меню гильдий и список ЛС не
сняты (пустые выгрузки), данные результатов поиска отсутствуют, профиль-попаут без текста,
остальные разделы настроек кроме «Голоса» не сняты. Поэтому часть чисел имеет код `[A]`
с обоснованием в `SPEC.md`, а не `[M]`.
