# ADR-3 — интерактивный вход по логину/паролю (дополнение к ADR-2)

Статус: **принято владельцем** (запрос 2026-10-23). Дополняет `ADR-2-auth.md`.
Риск ToS/блокировки принимается владельцем; работы — только на тестовом аккаунте.

## Контекст

Владелец просит вход как в оригинальном приложении: логин/пароль, captcha, 2FA, окно входа.
ADR-2 выбрал импорт токена; теперь добавляется **интерактивный** вход.

## Решение

Разрешить **ручной интерактивный вход** через штатные endpoint'ы Discord:

1. Пользователь вводит login/password в окне приложения.
2. `POST /auth/login`; при `captcha` — показываем штатный hCaptcha-виджет, пользователь
   решает его сам; токен капчи уходит в запрос.
3. При `mfa` — экран 2FA (`totp`, `sms`, `backup`, `password`), код вводит пользователь.
4. Успех → токен в keyring; пароль/код сразу затираются в памяти (best-effort).
5. Ошибки 401/429/сеть → понятные состояния, backoff, без автоматических повторов.

## Что запрещено (P0)

- Автоматическое решение/обход captcha, сторонние solver-сервисы.
- Подмена fingerprint/UA/anti-detect, прокси-ротация, массовые аккаунты.
- Сохранение пароля/2FA-кода в keyring, логах, DOM, ошибках, аналитике.
- Автоматические retry логина «в цикле», hammering.
- Вход в чужие аккаунты; только тестовый аккаунт владельца.

## Безопасность

- TLS только официальные хосты; никакой сети без окна.
- Пароль живёт только в памяти на время запроса; после ответа — overwrite.
- Токен — только keyring; `Debug`/логи редактируются.
- Капча — интерактивная, без обхода; 2FA — ввод пользователя.
- 429/401 не маскируются; UI показывает причину.

## Последствия

- Появляется зависимость от актуальности `/auth/*` и captcha-контекста; версия клиента
  фиксируется, поля проверяются RE-тестами.
- Возможна блокировка аккаунта; используется тестовый.
- Если Discord меняет captcha/2FA — фича отключается флагом, token-import остаётся.

## Acceptance

- окно входа соответствует дампу (поля, порядок, ошибки);
- 401 → «неверный логин/пароль», 429 → «подождите N с», captcha → виджет, MFA → экран кода;
- пароль не найден в DOM/логах/keyring после запроса;
- успешный вход → keyring → `/users/@me` → READY;
- logout → keyring.clear + stop supervisor.
