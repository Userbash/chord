# NET — сетевой отдел: устав, границы, этапы

Дата: 2026-10-23. PM: DeepSeek. Статус: формируется.
Цель: подключить сетевое взаимодействие Discord к ядру и GUI — вход, сессия, шлюз, REST, —
не ломая безопасность и не превращая проект в средство обхода блокировок.

## 1. Что уже есть в ядре

| Модуль | Что делает | Тесты |
|---|---|---|
| `discord-core::ws` | WS-клиент `ws://`/`wss://`, пайп zstd→ETF→dispatch | есть |
| `discord-core::gateway` | HELLO/IDENTIFY/HEARTBEAT/RESUME, сессия, эффекты | есть |

## 2. Границы (обязательно)

1. **Никаких средств обхода блокировок/анти-детекта**: не подделываем fingerprint, не обходим
   captcha, не автоматизируем массовые аккаунты, не маскируемся под официальный клиент
   сверх того, что требует протокол. «Защита» = корректные лимиты, backoff, честные заголовки,
   уважение 429/401, отсутствие утечек токенов.
2. **ToS**: Discord не разрешает сторонние клиенты для пользовательских аккаунтов. Поэтому:
   - основной путь — **импорт собственного токена владельца** (явное согласие, только локально)
     и/или **OAuth2/bot** для разрешённых сценариев;
   - автоматизацию логина паролем/captcha не делаем;
   - риск блокировки аккаунта фиксируется письменно; тестовый аккаунт — отдельный.
3. **Секреты**: токен только в keyring (libsecret), никогда в логах/репозитории/ошибках;
   в памяти — минимальное время; на диск — только через `discord-store`/keyring.
4. **Сеть**: только TLS, только официальные хосты Discord, без прокси-ротации и «обхода».
5. **Окно live**: подключение к живому Discord — только по согласованному окну владельца,
   с тестовым аккаунтом; окно фиксируется в `PM/window-runs.jsonl`.

## 4. Роли

- **NET-A** — reverse engineering логина/заголовков по дампу (`/home/sanya/re-deep`).
- **NET-B** — аудит ядра и карта «что вызывать» (без правок).
- **NET-C** — backend auth-команды + keyring.
- **NET-D** — frontend login UI.
- **NET-E** — live gateway (после ADR-2 и окна).
- **Codex-Security** — независимое ревью.

## 5. Критерий «полноценное приложение» (минимум)

- вход (токен владельца) → сохранение в keyring → `GET /users/@me` → gateway READY;
- восстановление сессии после перезапуска;
- logout с очисткой токена;
- отображение ошибок (401/429/сеть) без утечек;
- UI: экран входа + статус подключения; кнопки не мёртвые;
- ни одного токена в логах; лимиты/backoff соблюдены.
