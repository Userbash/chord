# Mechanism-to-library decisions

ARM follow-up: [ARM-BLOCKERS.md](ARM-BLOCKERS.md) is an explicit early intake and release gate.
Every dependency integration consults `LIB-ARM-03`; unknown ARM CPU/ABI/native support remains unqualified.

Baseline: `2b7cfb52`; primary documentation checked on 2026-11-15. These are candidates and guarded decisions, not installed application dependencies. Exact dependency integration is coordinator-owned and requires `LIB-GOV-02`.

## What remains custom

Discord-specific session/reconnect state, rate-limit policy, DAVE/MLS transitions, packet framing/replay rules, permission semantics, identifier/wire compatibility, navigation/secret policy and renderer behavior remain explicit application code. Libraries supply standard mechanisms; they do not replace the evidence that the application still fulfills these contracts.

## How a candidate is accepted

The leaf decision records exact provenance/version/features, security/license/MSRV status, each native target, the prior contract, a minimal prototype, independent differential/negative/boundary tests, performance/resource cost, net owned-code change and rollback. A qualification may correctly conclude “retain current implementation”; that outcome is useful and must not be mislabeled as a failed worker or forced migration.
