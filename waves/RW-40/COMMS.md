# RW-40 — COMMS: коммуникация отделов, приёмка, качество

Дата: 2026-10-24. PM: DeepSeek. Обязателен для всех отделов.

## 1. Единая точка правды

| Что | Где |
|---|---|
| Доска задач/статусы | `waves/RW-40/TASKS.md` |
| Контракты | `NET/AUTH-CONTRACT.md`, `DESIGN/DOM-CONTRACT.md`, `DESIGN/FUNCTION-MATRIX.md` |
| Решения/отклонения | `waves/RW-39/PM/DECISIONS.md` |
| Петли/эскалации | `waves/RW-39/PM/LOOP-LEDGER.md` |
| Политика тестов | `TEST-POLICY.md` |
| Журнал/состояние | `waves/STATE.md`, `PROJECT-CONTEXT.md` |

Устные решения не действуют. Всё, что меняет контракт/файлы/приоритет — запись в DECISIONS.

## 2. Формат задачи (бриф)

```
TASK <ID> — <одна цель>
ВЛАДЕЛЕЦ ФАЙЛОВ: <точный список>, остальное read-only
ВХОД: 2–4 файла/секции (не читать весь репозиторий)
RED: какая проверка падает и почему это правильно
GREEN: минимальный критерий
ЗАПРЕТЫ: чужие файлы, ослабление тестов, сеть, commit
EVIDENCE: команда → exit → путь лога
ОТЧЁТ: путь + 5–10 строк
```

## 3. Формат возврата (RETURN)

Возврат принимается только с:
1. `finding` (что не так);
2. `repro` — точная команда/вход;
3. `expected` / `actual`;
4. `scope` — какие файлы можно править;
5. номер итерации.

Без `repro` задача не возвращается в работу. Воркер не спорит правкой чужих файлов — спор
решается через PM.

## 4. Приёмка (ACCEPT)

PM принимает только при:
- red-лог + green-лог;
- targeted-тесты и общий гейт зелёные;
- тесты не ослаблены (диф тестов проверил не автор);
- md5 совпадают с отчётом;
- evidence приложен;
- для live — окно согласовано и записано в бюджет.

Запись: `DECISIONS.md` (ID, дата, что проверено, остаток).

## 5. Межотдельные стыки

| Стык | Контракт | Кто подтверждает |
|---|---|---|
| Design → Frontend | `LOGIN-SPEC`, `DOM-CONTRACT` | PM |
| Frontend ↔ Backend | `AUTH-CONTRACT`, `FUNCTION-MATRIX` | PM |
| Backend ↔ Core | типы/ошибки в `rest/*`, `auth.rs` | Backend+Core |
| Backend ↔ Network | `connect/READY`, close-коды | Network |
| Все → QA | `QA/PLAN-E9.md` | QA |

Изменение контракта: предложение → PM → `DECISIONS.md` → оба отдела → тесты.

## 6. Ритм

- Старт смены: прочитать `TASKS.md` + `PROJECT-CONTEXT.md` (не историю волн).
- Конец задачи: отчёт + обновление статуса в `TASKS.md` (делает PM).
- Через каждые 2 задачи: короткий чекпоинт в `PROJECT-CONTEXT.md` (что принято, что красное).
- Раз в волну: `STATE.md`/`db.jsonl` — Team Lead/координатор.

## 7. Эскалация

| Ситуация | Действие |
|---|---|
| 2 одинаковых отказа | смена подхода (инструмент/контракт/механизм) |
| 3-я попытка | запрещена, эскалация PM |
| Конфликт требований | PM + ADR, не правка чужих файлов |
| Нет исполнителя | задача в очередь, критический путь — Codex/PM |
| Баланс/среда | зафиксировать, не имитировать прогресс |

## 8. Качество

- TEST-POLICY: red-first, evidence, запрет ослабления тестов.
- Мутации для новых инвариантов; missed — карточка.
- Codex-Review: отдельный проход, P0/P1 только с file:line/repro.
- QA: матрица кнопок, live/AT-SPI, скриншот, метрики.
- Coverage: UI и Rust измерять отдельно; «coverage только src/**» не считать покрытием UI.

## 9. Кодекс общения

- Пишем факты и команды, не оценки («работает» → команда + exit).
- Не перекладываем вину: фиксируем сигнатуру и следующий шаг.
- Не расширяем scope молча.
- Не «зеленим» тесты и не обходим гейт.
- Блокер сообщаем сразу, с вариантами A/B.
