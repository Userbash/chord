## 2. Есть ли stream UI в дампе

**Отдельного UI стрима — нет.** В дампе есть только **вход в поток** и **строки настроек**:

1. `voice/ui/01-voice-panel.html` (61 403 Б, md5 `ef5a88b5…`) и `voice/ui-s2/01-voice-panel.html`
   (61 414 Б, `5a778c2b…`) — ряд действий панели: кнопки «Камера недоступна» (класс `fauxDisabled`,
   без заливки), «Продемонстрируйте свой экран» (`aria-pressed="false"`), «Начать активность»,
   «Открыть звуковую панель».
2. `ui8/23-settings-voice.json` (`0ee803c3…`) — секции «Камера» и «Стриминг»: селект
   «Нет видеоустройств», «Проверить видео», «Предпросмотр видео (всегда)» = вкл,
   «Показывать предпросмотр стрима» = вкл, «Приглушение стрима» = вкл + ползунок 1…100 = 50.
3. `voice/ui/01-candidates.json` (`a5757286…`) — `voiceChannelEffectsContainer__2f4f7` **833×469**,
   содержимое пустое (большой вид канала, где в оригинале были бы видео-тайлы).

Чего нет: превью, листа «Настройки стрима», меню качества, сетки тайлов зрителя, полноэкранного
режима, счётчика зрителей, включённой камеры, экранов ошибок захвата. Ни одного `STREAM_*` события
в 4 capture (1340 op0) и в RTC-кадрах — тоже нет.

## 4. Метки

| Метка | Значение | Примеры |
|-|-|-|
| `[T]` | токен проекта | `--btn-height`, `--z-modal`, `--modal-w-md`, `--space-4`, `--layout-tree-w` |
| `[M]` | пиксельный замер `01-joined.png` / 1.25 | кнопки ряда 79.2–80.0; заливка 26.4 при кнопке 32 |
| `[D]` | факт дампа | DOM-классы, 110 ключей модуля, ключи i18n, флаги фич |
| `[L]` | live-захват | op0/op2/op4, кодек AV1, 720p30/2.5 Мбит, stream key, 0 `STREAM_*` |
| `[S]` | код/протокол | `STREAM_*` схемы, `rid 50`/simulcast, `self_video`/`self_stream`, PT |
| `[A]` | наше решение/пробел | вся геометрия сцены, качество `auto/source`, зрители только числом, X11-путь |
| `[F]` | заморожено | не применимо к этой карточке (код не менялся) |

Правило соблюдено: **ни одно `[M]`/`[A]` не выдано за паритет**. Экранов стрима в дампе нет,
поэтому паритет по ним прямо не заявляется (§0.2, §11.1 документа).

## 5. Подтверждено vs `[A]`

| Тема | Подтверждено | Не подтверждено (`[A]`) |
|-|-|-|
| rid/ssrc | `rid:"100"` строка, `ssrc/rtx` = audio+1/+2 (17843/4/5, 9208/9/10) | `rid:"50"` живьём не включался |
| quality | `quality:100` в op0/op2 и движке | числовые значения enum `eq.Y4`/`eq.Cl`; выбор quality **для зрителя** |
| AV1 | согласован `video_codec:"AV1"`, PT 101/102, enc+dec | реальный поток AV1 не снимался; H265 у зрителей |
| stream key | `guild:<guild>:<channel>:<user>` (HTTP-cache) | какой вызов стартует/останавливает стрим, коды ответов |
| `STREAM_*` | поля всех 4 событий (по коду) | ни одного живого события; семантика `viewer_ids`/`paused` |
| захват | портал/PipeWire/`ScreenshareHelper` в модуле | реальный захват; X11-путь; системный звук; vaapi |
| камера | `self_video`, `getVideoInputDevices`, строки настроек | включение камеры, превью, права ОС |

## 7. Linux

- **Wayland** — основной путь: `presentNativeScreenSharePicker` + портал `org.freedesktop.portal.ScreenCast`
  → `pw_stream_*` (`BaseCapturerPipeWire`); PipeWire линкуется `dlopen`, в NEEDED нет.
- **X11** — нативного пикера нет; путь захвата не подтверждён (`[A]`) — портал или свой XShm/XComposite.
- **`screen_previews`/`window_previews` — win32-only**: на Linux превью экранов/окон **недоступны**,
  миниатюры стримов не рисуем; источник показывает только системный диалог.
- **Камера** — v4l2, превью только в листе после клика; `getUserMedia` в UI запрещён.
- **Системный звук** — строки `soundshare*`; `soundshare_loopback` win32-only → в MVP не шарим.
- **vaapi/gamescope** — `isVaapiEnabled()` не проверялся; gamescope требует gamescope+vaapi+PipeWire-сокет.

## 8. Тест-план

- **G2 (36 кейсов, fake)**: `SL-01…SL-16` (вход/лист/превью/старт/стоп/пауза/счётчик/качество),
  `ST-01…ST-06` (тайлы, пустая сцена, fullscreen, пауза, «заполнен»), `SC-01…SC-06` (камера:
  превью→включение→отмена), `SE-01…SE-04` (ошибки), `SA-01…SA-04` (a11y).
- **G4 (12 кейсов)**: `SG-01…SG-12` — нет захвата при монтировании, нет `mediaDevices`, нет записи,
  нет `getScreenPreviews`, ключи не в UI, стоп освобождает, нет авто-рестарта, нет миниатюр.
- **G5 (10 кейсов, лаборатория)**: `SP-01…SP-10` — портал/PipeWire, X11, v4l2, энкод, RTP rid/rtx,
  sink wants 20 fps, второй RTC, зритель, системный звук.
- Fake vs live: на фейке проверяются все состояния/ошибки/тайлы/камера; **только live** — реальные
  `STREAM_*`, второй RTC endpoint/token, захват, декод/звук зрителя, согласование AV1 и вызов старта.

## 9. Пробелы (главные)

1. **Экранов стрима нет в дампе** → вся геометрия сцены/листа/тайлов/fullscreen `unmeasured`,
   паритет не заявлен (SG-01).
2. **`STREAM_*` не наблюдались live** (0 событий в 4 capture) и **не установлено, какой вызов
   стартует/останавливает стрим** (SG-02, SG-06); семантика `viewer_ids`/`paused` неизвестна (SG-05).
3. **Linux: `screen_previews`/`window_previews` win32-only**, X11-путь захвата не подтверждён,
   камера ни разу не включалась (SG-07, SG-08, SG-09).
4. Числовые значения `quality` для `rid:"50"` неизвестны (SG-03); выбор качества для зрителя — нет (SG-04).
5. Системный звук — только строки фич, loopback win32-only (SG-10).
6. Права канала на стрим/камеру (`canStream`/`canVideo`) не подтверждены (SG-12).
7. `codec survey is not available` в логе — смысл не установлен (SG-11).
8. Меню качества и fullscreen-поведение не сняты (SG-14, SG-15); стрим+камера одновременно — нет (SG-16).
9. Экраны ошибок захвата не сняты — только строки каталога (SG-13).
10. `spec` не сверялся с живым API; после N3-07 нужна сверка (SG-17).

## 10. Риски (кратко)

Скрытый захват и захват после ошибки (R-01/R-02), необработанный отзыв согласия в ОС (R-03),
случайный шаринг чувствительного окна (R-04), утечка `stream_key`/`token` (R-05), перечисление
окон как слежка (R-06), миниатюры как сеть и чужие кадры (R-07), счётчик как список зрителей (R-08),
запись «для отладки» (R-09), камера без подтверждения (R-10), тихий стоп без события (R-11).
