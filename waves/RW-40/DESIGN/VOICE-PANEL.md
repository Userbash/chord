## 1. Резюме

V-06-UI сдаётся как **честная fake-панель**: она умеет рисовать 12 состояний,
участников, speaking, mute/deafen, ping, PTT-индикацию и ошибки из store, но
**не имеет** голосового backend'а. В собранном приложении панель обязана оставаться
`disabled`: имитировать «подключено» без сессии запрещено (`G6-REPORT §3.7`).

Ядро — четыре состояния, остальные восемь — уточнения/оверлеи:

```text
        join (service)                 store: connected
 idle ──────────────────▶ connecting ──────────────────▶ connected
   ▲                           │                              │
   │ store: idle               │ store: error                 │ store: error
   │ (leave подтверждён)       ▼                              ▼
   └──────────────────────── error ◀──────────────────────── error
                                 │
                                 └── reconnect (service.join) → connecting
```

`loading`, `reconnecting`, `empty`, `no-permission`, `ptt-required`,
`device-missing`, `server-mute` и `disabled` не ломают эту схему: это либо
транзиент, либо оверлей поверх сессии, либо сборка без сервиса (§2).

Ключевые инварианты:

1. Панель **не** строит endpoint/token/ssrc и не вызывает IPC/сеть/медиа.
2. `data-state` — единственный источник стилей; состояние приходит из store,
   панель не выводит «подключено» из клика.
3. Join/leave/reconnect не оптимистичны: до события store состояние не меняется.
4. `speaking` — только op5-флаг (bool или число `> 0`); панель не считает речь
   по громкости, анимации или PTT.
5. Серверный mute сильнее локального; deafen и mute — независимые флаги.
6. Ошибка не глотается: есть код/регион/сообщение и, где положено, retry.
7. Fake V-08 **не** равен voice parity (§10).

## 2. Модель состояния

### 2.1 Store: поля и владельцы

| Поле | Тип | Кто пишет | Как использует панель | Метка |
|-|-|-|-|-|
| `state` | 12 значений §2.2 | gateway/service reducer; в спайке — fake/tests | `data-state`, видимость блоков | `[F]` |
| `guildId` / `channelId` | string | событие входа | ссылка канала, guard retry | `[C]` |
| `channelName` | string | событие входа | текст ссылки + `title` | `[C]` |
| `participants` | массив §4.1 | `VOICE_STATE_UPDATE`/op5 | список, счётчик, mute/speaking | `[F]` |
| `ping` | number \| null | сервис статистики (V-06-STATS) | скрытое значение + `data-quality` | `[F]` |
| `selfMute` / `selfDeaf` | boolean | op4-подтверждение | `aria-checked`, `data-self-*` | `[F]` |
| `serverMute` | boolean | серверное событие | блокировка mute, текст строки | `[F]` |
| `ptt` | `idle\|held\|blocked` | сервис/локальный gate | `data-ptt`, live-текст | `[F]` |

Правила store (`[C]`/`[F]`):

- снапшот иммутабельный, подписка синхронная, слушатели вызываются после коммита;
- неизвестное `state`/`ptt` **игнорируется**, панель не зависает вне контракта;
- участник без `id`/`name` — ошибка `IPC_FAILED`, а не пустая строка;
- `ping`: только конечное число `≥ 0`, иначе `null`;
- панель пишет в store только `error` при отказе join/reconnect (в текущей
  однополевой модели). Для leave/mute/deafen/enablePtt запись фазы **запрещена**
  (§8.5): иначе неудачный mute выглядит как потеря сессии.

### 2.2 Двенадцать состояний: класс, смысл, источник

| `data-state` | Класс | Смысл | Статус-текст | Метка |
|-|-|-|-|-|
| `idle` | база | сессия есть, в канале нет | блок скрыт | `[D]` |
| `loading` | транзиент | вход принят, ответа ещё нет | skeleton, текста нет | `[A]` |
| `connecting` | транзиент | RTC/голос подключается | «Подключение...» `1zFMqU` | `[D]` |
| `connected` | база | в канале, сессия жива | «Голосовая связь подключена» `daXg45` | `[D]`/`[M]` |
| `reconnecting` | транзиент | RESUME/переподключение | «Переподключение» `PygWIS` | `[D]` |
| `empty` | оверлей | в канале 0 участников | «Сейчас в голосовом чате никого нет» `wM2WTM` | `[D]` |
| `error` | фолт | вход/сессия не удались | polite «Голосовая связь отключена» `juL9/L` + alert `S69lJR` | `[D]`/`[F]` |
| `no-permission` | фолт | нет права входа | «У вас нет права присоединиться…» `7/2/3M` | `[D]` |
| `ptt-required` | гейт | канал требует PTT | «Требуется режим рации» `NYklhr` + `dpiBNy` | `[D]` |
| `device-missing` | оверлей | вход исчез, сессия жива | `bgn75v` + «Убедитесь…» `MA+OZh` | `[D]` |
| `server-mute` | оверлей | сервер заглушил микрофон | «У вас откл. микрофон на сервере» `+JQCa/` | `[D]` |
| `disabled` | сборка | voice-сервиса нет | «Голосовой канал недоступен в этой сборке» | `[A]` |

`empty`, `server-mute`, `device-missing`, `ptt-required` — не отдельные фазы
соединения, а **проекции** живой сессии. В fake store они выставляются явно
(так заморожено тестами); в будущем reducer/precedence считает их из флагов.
Панель **не** пересчитывает `data-state` из флагов: это разошлось бы с `[F]`.

### 2.3 Приоритет проекций (для reducer/selector, не для render)

Если несколько условий истинны одновременно, одно значение выбирается так
(`[A]`, требует подтверждения PM):

1. `disabled` — сборка без сервиса;
2. `error`;
3. `no-permission`;
4. `reconnecting`;
5. `loading`;
6. `connecting`;
7. `ptt-required`;
8. `device-missing`;
9. `server-mute`;
10. `empty`;
11. `connected`;
12. `idle`.

Инварианты, которые панель вправе ожидать от store (иначе это дефект
производителя событий, а не повод для UI-догадок):

- `state="empty"` ⇒ `participants.length === 0`;
- `state="server-mute"` ⇒ `serverMute === true`;
- `state="connected"` ⇒ `channelId !== ""`;
- `state="error"`/`"no-permission"` ⇒ канал не считается активной сессией;
- `ptt="held"` допустим только при наличии сервиса/сессии.

### 2.4 Переходы

| ID | Из | Событие/действие | В | Guard | Побочный эффект |
|-|-|-|-|-|-|
| T-01 | — | boot | `disabled` | `service === null` | `aria-disabled`, вход заблокирован |
| T-02 | — | boot | `idle` | сервис есть, store пуст | блок связи скрыт |
| T-03 | `idle` | клик join | без смены | `channelId !== ""`, не pending | ровно 1 `join(channelId)`; ждём store |
| T-04 | `idle`/`loading` | store: вход принят | `loading`/`connecting` | — | skeleton/статус, leave активна |
| T-05 | `loading`/`connecting` | store: сессия | `connected` | — | канал, ping, участники |
| T-06 | `connected`-подобное | store: RESUME | `reconnecting` | — | список остаётся last-known |
| T-07 | `reconnecting` | store: сессия | `connected` | — | ping/список обновляются, без «прыжка» |
| T-08 | любое live | store: `error` | `error` | — | alert `S69lJR`, retry, фокус по §3.5 |
| T-09 | `loading`/`connecting` | store: 403 | `no-permission` | — | retry скрыт, 0 вызовов сервиса |
| T-10 | вход/сессия | store: PTT-канал | `ptt-required` | — | CTA `E3Y7NH` |
| T-11 | `connected`-подобное | потеря входа | `device-missing` | сессия жива | hint `MA+OZh`, leave активна |
| T-12 | `device-missing` | вход вернулся | `connected`/`empty`/`server-mute` | по §2.3 | без автопереключения устройства |
| T-13 | `connected`-подобное | `serverMute=true` | `server-mute` | — | mute `aria-disabled`, deafen жив |
| T-14 | `server-mute` | `serverMute=false` | `connected`/`empty` | — | mute снова доступен |
| T-15 | `connected` | участников 0 | `empty` | — | строка `wM2WTM`, ping остаётся |
| T-16 | `empty` | участники > 0 | `connected` | — | список и счётчик |
| T-17 | `error` | клик reconnect | без смены | `channelId !== ""`, не pending | ровно 1 `join(channelId)` |
| T-18 | `error`/`no-permission` | клик leave | без смены | не pending leave | 1 `leave()`; ждём store |
| T-19 | любое live | store: `channel_id = null` | `idle` | — | очистить канал/ping/участников |
| T-20 | `ptt-required` | клик enable-ptt | без смены | метод есть | 1 `enablePtt()`; ждём store |
| T-21 | `disabled` | любой клик | `disabled` | — | 0 вызовов сервиса; причина в live-регион |
| T-22 | любое | неизвестное `state`/`ptt` | без смены | — | store игнорирует патч |

Правила:

- **Нет оптимистичных переходов.** Клик — это запрос; состояние меняет только
  store-событие. Исключение — отказ join/reconnect: панель выставляет `error`,
  потому что другого сигнала в текущем контракте нет (`[C]`), и это должно быть
  идемпотентно.
- `loading` — наше состояние `[A]`: Discord-строки для него в дампе нет.
- Таймауты/backoff reconnect — **не** в панели: это сервис/V-06-STATS. Панель не
  заводит `setTimeout` и не считает попытки.
- `idle` и `disabled` — разные вещи: `idle` = сервис есть, сессия не начата;
  `disabled` = сервиса нет вообще.

### 2.5 Запрещённые переходы

| Запрет | Почему |
|-|-|
| `idle → connected` по клику | нет подтверждения сессии; это ложь |
| `connected → idle` по клику leave | выход подтверждается `VOICE_STATE_UPDATE.channel_id=null`/close |
| `connected → error` из-за неудачного mute/deafen/leave | ошибка действия ≠ потеря сессии (§8.5) |
| `error → connected` по клику reconnect | только по событию store |
| `no-permission → connecting` по retry | прав нет; 0 вызовов сервиса |
| `disabled → любое live` | в сборке нет сервиса |
| `server-mute → connected` по локальному клику | серверный mute сильнее; снимет только сервер |
| `empty` при `participants.length > 0` | противоречие данным |

### 3.3 Live-регионы и громкость объявлений

| Регион | Политес | Что объявляет | Что **не** объявляет |
|-|-|-|-|
| `#voice-status` | polite, atomic | смену фазы (connecting/connected/reconnecting/error phase) | значение ping (target: `aria-live="off"` на `#voice-ping-value`) |
| `#voice-a11y` | polite | результат действия, PTT held/blocked, причина disabled | каждое op5-событие |
| `#voice-error` | assertive (role alert) | причину фейла: `S69lJR` или generic action error | повтор фазы |
| `#voice-empty` | status | появление пустого канала | счётчик участников |
| `.voice-user` | нет live | — | смена speaking не должна «болтать» |

Проблема текущего кода `[C]`: `#voice-ping-value` лежит внутри polite-региона
`#voice-status`. При обновлении ping раз в секунду live-регион будет читать
«93 ms», «93 ms», … Это шум. Минимальное исправление G2: `aria-live="off"` на
значении (доступность через `aria-describedby` сохраняется). Менять `aria-live`
самого `#voice-status` нельзя без правки `[F]`-теста.

`#voice-error` не должен дублироваться вторым assertive-регионом. Ошибка сессии
(`S69lJR`) и polite-фаза «Голосовая связь отключена» — разные сообщения (причина
и фаза), а не два одинаковых.

неприменим (§3.6).

### 3.5 Возврат фокуса

Правило R1: рендер **не** двигает фокус, пока сфокусированный узел остаётся
видимым. Правило R2: если узел скрыт/удалён, фокус переходит по таблице.

| Триггер | Куда вернуть | Почему |
|-|-|-|
| join/reconnect отклонён, фокус был на join/reconnect | `#voice-reconnect` | продолжить retry (заморожено тестом) |
| join принят, `#voice-join` скрыт | `#voice-leave` | сессия началась, выход доступен |
| leave подтверждён, `#voice-leave` скрыт | `#voice-join` | вернуться к входу |
| reconnect принят, кнопка скрыта | `#voice-leave` | сессия восстанавливается |
| enable-ptt принят, кнопка скрыта | `#voice-leave` | сессия продолжается |
| активный элемент стал `hidden` без правила выше | `#voice-panel` (`tabindex="-1"`) | не терять фокус в `body` |
| попап устройств (V-07) закрыт | шеврон, открывший его | ARIA-контракт меню |

Уточнения:

- текущий код двигает фокус на reconnect при **любом** отказе join, если фокус
  был внутри панели. Target: только если фокус был на join/reconnect; иначе
  оставить на месте (иначе клик по mute при ошибке входа «телепортирует» фокус).
- `#voice-panel` нужен `tabindex="-1"` как fallback; сейчас его нет `[C]`.
- ошибка (`role=alert`) не получает фокус: она объявляется, но не крадёт его.
- фокус-ринг: 2px `--focus-ring`, offset 2 `[T]`; padding панели 8 по горизонтали
  вмещает ring 4 без обрезки. Список участников не фокусируем, поэтому
  `overflow` его не режет.
- `:focus-visible` — только клавиатура; клик мышью не должен показывать ring.
- если в V-07 строки станут интерактивными, фокус восстанавливается по
  `data-user-id`, а не по индексу; сейчас строки не tab-stop.

## 4. Участники

### 4.1 Данные строки

| Поле | Тип | Обязательно | Правило |

Запрещено: аватар-URL, роли, цвет ника, статус присутствия, «deaf» другого
участника — этих полей нет в контракте события; выдумывать их нельзя (§5.1

### 4.2 Порядок, лимит, overflow

- Своя строка — первая; остальные — в порядке прихода событий (стабильная
  сортировка; алфавит не применяем) `[A]`.
- В панели максимум **6** строк (`PARTICIPANT_LIMIT`, `[A]`/`[F]`); остальные
  сворачиваются в строку «Ещё n участник(ов) в голосовом чате» (`R0h4pE`).
- Плюрализация: 1 — «участник», 2–4 — «участника», 5–20 — «участников»,
  21 — «участник», 22–24 — «участника» и т.д. (`[C]`, покрыто тестом).
- `#voice-overflow` — вне `role="list"`; не live, чтобы не объявлять каждый
  приход.
- Виртуализации нет: 6 строк — предел.
- Строки не интерактивны: нет `tabindex`, нет контекстного меню, нет
  «заглушить участника» — для этого нужны права и backend (V-07/out of scope).

### 4.3 Приоритет mute

| Условие | `data-mute` | Видимый текст | `aria-label` |
|-|-|-|-|
| своя + `serverMute`/`server-mute` | `server` | «У вас откл. микрофон на сервере» `+JQCa/` (target) | имя + этот текст |
| своя + `selfMute` | `self` | «Этот микрофон отключён» `tjtv3P` | имя + `tjtv3P` |
| другой + `mute=server` | `server` | «микрофон отключён на сервере» `[A]` | имя + текст `[A]` |
| другой + `mute=self` | `self` | «микрофон отключён» `[A]` | имя + текст `[A]` |
| иначе | `none` | — | только имя |

Текущий код для своей server-mute строки использует общий текст
«микрофон отключён на сервере» `[C]`; target — `+JQCa/`, потому что это своя
строка и в дампе есть отдельная строка. Это правка G2 + новый тест; старые
тесты не конфликтуют.

Deafen **не** выключает `aria-checked` микрофона и не показывается иконкой у
других: это независимый флаг, а данных о deaf других в контракте нет.

### 4.4 Speaking

| Свойство | Значение | Метка |
|-|-|-|
| Источник | op5 `{user_id, ssrc, speaking}`; bool или число | `[S]` |
| Правило | `speaking === true` или число `> 0` | `[F]` |
| Атрибут | `data-speaking="true\|false"` только у этой строки | `[F]` |
| Визуал | кольцо 2px `--positive` вокруг аватара 32, без пульсации | `[A]`/`[F]` |
| Движение | 120 мс `--motion-fast`; `prefers-reduced-motion` → 0 | `[T]`/`[F]` |
| Доступность | в `aria-label` строки добавляется «говорит» | `[F]` |
| Нет op5 | ни у кого нет `data-speaking="true"` | `[F]` |
| PTT `held` | локальный индикатор своей строки; **не** доказательство, что слышат | `[A]` |

`PTT held` не должен превращаться в «говорит» у чужих строк. Если PTT-индикатор
показывается кольцом, он обязан дублироваться текстом в `#voice-a11y`
(«Режим рации: микрофон активен»), иначе состояние только цветом.

Speaking-обновления приходят часто. Панель не анимирует смену масштаба и не
делает live-объявлений; перерисовка не должна сбрасывать `scrollTop` списка
(§7.3).

### 4.5 Пустое состояние

- Показывается только при `state="empty"` **и** `participants.length === 0`.
- `<p id="voice-empty" role="status">` — вне списка, текст `wM2WTM`.
- В `empty` ping и leave остаются доступны: это живая сессия, просто без людей.
- Если `state="empty"`, но участники есть — это нарушение инварианта §2.3;
  панель не должна одновременно показывать строки и «никого нет». Текущий код
  в этом случае покажет строки, а `#voice-empty` скроет `[C]`; статус-текст
  останется `wM2WTM` — это дефект производителя состояния, а не UI-логика.
- Дублирование `wM2WTM` в `#voice-status-label` и `#voice-empty` — известный
  дефект `[F]`-контракта (§13 Q-3); в V-06 не правим без смены спеки/теста.

### 4.6 Privacy строки

Строка рендерится только из полей события. Нет запроса профиля, аватара, ролей;
нет `console.log` имени/устройства. Инициалы — декоративны и не должны быть
единственным носителем имени (имя есть текстом и в `aria-label`).

## 5. Ping

| Свойство | Значение | Метка |
|-|-|-|
| Элемент | `#voice-ping` (`button`), `aria-describedby="#voice-ping-value"` | `[D]`/`[F]` |
| Видимое | только иконка; число скрыто | `[D]` |
| Формат | `{round(ping)} ms`, латиница «ms» | `[D]`/`[F]` |
| Валидность | конечное число `≥ 0`; иначе нет данных | `[C]` |
| Нет данных | `aria-disabled="true"`, `data-quality` отсутствует, значение пустое | `[F]` |
| Пороги | `≤120 fine`, `121…250 average`, `>250 bad` | `[A]`/`[F]` |
| Цвет | `--positive` / `--warning` / `--danger` | `[T]`/`[F]` |
| Обновление | не чаще 1/с; без анимации цифр; панель не заводит таймер | `[A]` |
| Источник | **не установлен**; гипотезы RTC/RTCP | `[A]` |

Видимость по состояниям (target):

- показываем значение в `connected`, `empty`, `server-mute`, `device-missing`,
  если `ping !== null`: серверный mute или пустой список не рвут соединение;
- в этих же состояниях при `ping === null` кнопка остаётся, но
  `aria-disabled="true"` и без значения (заморожено тестом для `connected`);
- **скрываем** (`hidden`, узел остаётся в DOM ради `[F]`-проверки `disabled`)
  ping в `loading`, `connecting`, `reconnecting`, `error`, `no-permission`,
  `idle`, `disabled` — там нет данных, а в `error` он ещё и отнимает ширину у
  leave/reconnect;
- текущий код показывает ping **только** в `connected` и всегда держит кнопку
  в DOM `[C]` — это скрывает качество связи в `server-mute`/`empty` и мешает в
  `error`; исправление G2 + новые тесты V6-11/12/23, старые тесты не ломаются.

Клик по ping: в V-06 статистики нет. Кнопка не должна быть «мёртвой»: по клику
объявляем в `#voice-a11y` «Статистика соединения недоступна в этой сборке»
`[A]` (новую строку согласовать с PM). Альтернатива — сделать ping
неинтерактивным, но это ломает `[F]`-Tab-порядок, поэтому не предлагается.

Формат `93 ms` — отображение, а не доказательство совпадения с Discord. Пороги
120/250 — наши числа (VG-06), паритет не заявлен.

типичный `connected` с 6 строками ≈ 275–300, максимум с overflow/actions/
2-строчным статусом ≈ 335. Это **не** 150 из дампа: у нас в панели есть список
участников, у Discord он в другом месте/свёрнут.

Политика:

1. Панель не должна выталкивать `#user-bar` за экран. Target CSS:
   `.voice-panel { flex: 0 1 auto; min-height: 0; }`,
   `.voice-participants { flex: 0 1 auto; min-height: 0; overflow-y: auto; }`.
   Тогда при нехватке высоты сжимается **только список**, а статус и user row
   остаются.
2. При обычной высоте список показывает до 6 строк и не скроллится; при
   коротком окне — скроллится, `scrollbar-width: thin`.
3. `#voice-overflow` («Ещё n») остаётся снаружи списка: он не должен скроллиться
   вместе со строками.
4. `scrollTop` списка сохраняется при перерисовке speaking/mute. Сейчас
   `replaceChildren` каждый рендер `[C]`; при 6 строках это дёшево, но позиция
   скролла может сбрасываться. G2: сохранять `scrollTop` или патчить строки по
   `data-user-id`.
5. Гнездовой скролл: `overscroll-behavior: contain` на списке `[A]`, чтобы
   колесо над списком не уводило дерево каналов; при этом на краях списка
   прокрутка не «протекает». Если PM хочет обратное — поменять одним правилом.
6. `#voice-panel` не получает `overflow: hidden` (иначе срежется focus-ring).
7. При высоте < 480 CSS px панель физически не гарантирует все блоки; это
   ограничение shell, а не панели. Рекомендованный минимум — 480; PM
   подтверждает (§13 Q-9).

### 7.4 Узкое окно < 720: панель исчезает вместе с деревом

`style.css` скрывает `#channel-tree` при `max-width: 719px`, а панель живёт
внутри дерева. Следствие: на узком окне голосовой панели нет вообще, включая
«Отключиться». Это не баг CSS панели, а ограничение shell. Варианты: (а) принять
для desktop-only спайка; (б) вынести панель в `#user-bar`/отдельный host (G2+TL);
(в) не скрывать панель, скрывать только `tree-scroll`. Решение — PM (§13 Q-9).
В V-06 fake это не проверяется (DOM-шим не считает media queries).

### 7.5 Слои и offset

| Слой | Значение | Метка |
|-|-|-|
| Панель | в потоке, `--z-base` | `[T]` |
| Попап устройств (V-07) | `--z-popover` 100 | `[T]` |
| Tooltip | `--z-tooltip` 300 | `[T]` |

Правила offset:

- панель примыкает к левому/правому краю колонки дерева (0), снизу — к
  `#user-bar` (0); отступов 6.4, как в Discord, нет (D-01);

## 8. Ошибки, retry и отказ действий

### 8.1 Таксономия

| Ситуация | Состояние | Регион/текст | Retry | Фокус |
|-|-|-|-|-|
| join отклонён сервисом | `error` | alert `S69lJR`; polite `juL9/L` | `#voice-reconnect` | reconnect, если фокус был на join/reconnect |
| join: нет прав (событие) | `no-permission` | статус `7/2/3M` | нет | остаётся, куда указывал |
| reconnect исчерпан (событие) | `error` | alert `S69lJR` | да | reconnect |
| leave отклонён | **без смены** | action-error `[A]` | пользователь жмёт leave снова | остаётся на leave |
| mute/deafen отклонён | **без смены** | action-error `[A]`; `aria-checked` из store не меняется | повторный клик | остаётся |
| enablePtt отклонён | **без смены** (`ptt-required`) | action-error `[A]` | повторный клик | остаётся |
| вход потерян | `device-missing` | `bgn75v` + `MA+OZh` | mic-test (без захвата) | — |
| серверный mute | `server-mute` | `+JQCa/` | нет (снимает сервер) | — |
| сборка без сервиса | `disabled` | `[A]`-текст | нет | join остаётся, причина в a11y |
| пустой канал | `empty` | `wM2WTM` в списке | нет | — |

Action-error `[A]`: одна generic-строка «Не удалось выполнить действие. Повторите
попытку.» в `#voice-error` (`role=alert`), без смены `data-state`. Это лучше, чем
текущее «любой reject → error» `[C]`: неудачный mute не должен выглядеть как
потеря голосовой сессии.

### 8.2 Правила retry

- один in-flight join/reconnect; повторный клик игнорируется (заморожено `[F]`);
- retry требует непустой `channelId`; иначе кнопка `aria-disabled` и объяснение
  в `#voice-a11y`, `join("")` запрещён;
- retry не меняет `data-state` до события store;
- `no-permission` не имеет retry: права не появятся от повторного клика; ноль
  вызовов сервиса (заморожено `[F]`);
- таймаут/backoff — сервис, не панель; панель не считается «зависшей» и не
  подменяет состояние по таймеру;
- после `error` пользователь всегда может `leave` (не заперт).

### 8.3 Копирайт и безопасность

- Тексты ошибок — только из `copy`/`authored_copy`; серверные строки не
  вставляются в DOM (иначе XSS/утечка).
- Все динамические значения — `textContent`/`setAttribute`, без `innerHTML`.
- `href` канала строится только из `guildId`/`channelId` и всегда начинается с
  `#/channels/`; `javascript:` невозможен.
- Имена участников не логируются; устройства в V-06 не перечисляются.
- `role=alert` — один; не дублировать ошибку в `#voice-status` тем же текстом.

### 8.4 Ошибка и фокус

- alert не получает фокус;
- если фокус был на кнопке, которая после ошибки скрыта, — вернуть по §3.5;
- если фокус был на mute/deafen, он остаётся там (не «телепорт» на reconnect);
- после retry фокус остаётся на reconnect, пока кнопка видима; после успеха
  (кнопка скрыта) — на leave.

### 8.5 Отказ действия ≠ отказ сессии

Явно разделяем:

| Событие | Меняет `data-state`? | Сообщение |
|-|-|-|
| join/reconnect reject | да, `error` | alert `S69lJR` |
| leave reject | **нет** | generic action-error |
| mute/deafen reject | **нет** | generic action-error |
| enablePtt reject | **нет** | generic action-error |
| store `error` (сессия) | да | alert `S69lJR` |

Это устраняет текущий дефект `[C]`, где leave/mute reject переводит панель в
`error` и скрывает ping/список, хотя сессия может быть жива.
