### 2.2 Пояснения к строкам

- **#1.** `markServerUnreadHook`/`markUnreadHook` в каталоге — analytics-хуки, **не**

  Не выводить право из роли/канала. Что считается ack (гильдия/канал/сообщение) — `[RE]`.

  контракт backend). Нет поля в payload → `false`. **`canInvite=true` без принятого диалога

  использовать. Если PM выберет toggle — отклонение от D1, отдельное решение `[A]`.
  Чтение состояния есть `[D]`; блокер — проекция IPC + запись (§0.5 п.1–2, п.6).
- **#4.** Вторая строка — **текущий уровень**, а не название опции. Уровни в каталоге:
  «Все сообщения» `n/bTaY`, «Только @упоминания» `6fQPhu`, «Ничего» `CtVGyQ` `[D]`;

### 2.3 Инварианты disabled / capability / owner / confirm

1. Неизвестная capability = `false`; пункт `aria-disabled="true"`, `tabindex="-1"`,
   **клик и Enter/Space — no-op**, запрос не уходит `[A]`. Guard обязателен в двух местах:
   диспетчер `[data-action]` (`actions.js:714-731`) и сам обработчик (защита от прямого
   вызова из теста/кода).
2. `aria-disabled` не заменяет `disabled` у кнопок отправки в диалогах: там именно
   `disabled` `[A]`.
3. `owner` влияет **только** на #9. Для остальных пунктов owner не special-case, пока
   backend не отдаст отдельный флаг `[A]`.
4. Self-пункты (1, 3–8, 10) не гейтятся правами. Их disabled-причина — отсутствие
   контракта/реализации, а не «нет прав».
5. **Причина disabled обязательна и машиночитаема**: `data-disabled-reason` ∈
   `not-implemented` | `capability-unknown` | `owner`. Приоритет: `owner` (#9) >
   `capability-unknown` (#2, пока capability не `true`) > `not-implemented`.
   Человекочитаемый текст — `aria-describedby` на скрытый узел **и** `title` `[A]`;
   узел переиспользуется по причине (id вида `menu-reason-not-implemented`), текст не
   дублируется в каждом пункте.
6. `refreshMenuState()` пересчитывает состояние **при каждом открытии**: ни один
   disabled-пункт не остаётся с `tabindex="0"`, ни один enabled — без `tabindex="0"`
   ровно у одного (roving-вход).
7. **Confirm** только у #9 (`alertdialog`). #1/#3/#4/#5/#7 — мутации без confirm (по
   `[D]`-паттерну Discord), #2 — confirm внутри G-06 (если появится), #6/#8 — поверхность
   `[RE]`, confirm не выдумывать.
8. #10 не подтверждается; успех — только resolved `writeText`.

## 3. Восемь неактивных пунктов: fake vs blocked

### 3.0 Общие правила (для всех 8)

Состояния: `disabled(reason)` → `idle` → `pending` → `success | error | timeout`.
Optimistic-мутации запрещены: UI меняет состояние только после 2xx/успешного локального
действия. Двойной submit игнорируется, пока `pending`.

Ошибки приходят **типизированно** (`{kind}`), не HTTP-текстом. Реально существуют три
типизированных контракта: `InviteError`, `EnterGuildError`, `LeaveGuildError`; объединение
вариантов: `unauthorized | missingToken | forbidden | notFound | rateLimited{retry_after_ms} |
client{status} | server{status} | network | storage | invalidResponse | invalidArg`.
Для пунктов без команды backend-ошибки невозможны; fake обязан использовать ту же форму
`{kind}` `[A]`. Разбор тела/текста ошибки запрещён.

| Случай | Поведение и текст | Метка |
|---|---|---|
| 401 | существующий auth-gate; диалог/меню закрыть, код не сохранять, запрос не повторять | `[A]` |
| 403 | диалог/меню остаются, «Недостаточно прав для выполнения запроса.» `PW7+do` (для leave — своя строка §3.9) | `[D]`/`[A]` |
| 404 | только там, где объект адресуем (инвайт/гильдия); иначе не показывать | `[A]` |
| 429 | «Слишком много попыток. Повторите через {n} с.», `n` — целые секунды из `retry_after_ms`; триггер/кнопка disabled до 0; затем **один** ручной повтор; авто-ретраев нет | `[A]` |
| 5xx | «Сервер не ответил. Попробуйте ещё раз.» + ручной повтор | `[A]` |
| network | «Сетевое подключение ограничено или недоступно.» `1BRkQ1` + повтор | `[D]` |
| timeout/unknown | «Результат неизвестен…», **никогда** не успех, никаких мутаций | `[A]` |

Fake vs live: fake — инъекция сервиса/состояния в тесте, без сети и без записи в
прод-состояние; live — только в согласованном окне после RE. Зелёный fake не повышает
`[A]/[RE]/[L]` до паритета.

### 3.2 #1 Пометить как прочитанное

Gate: маршруты ack есть `[S]` (§1.3), но что считается ack, ответ и коды — `[RE]`.
Состояния: `disabled` сейчас; при появлении контракта — `pending` → 2xx → статус `M3tKAP`;
ошибка оставляет непрочитанное как есть. 403 — generic `PW7+do`; 429 — общий countdown;
timeout — «результат неизвестен». Fake: запись `{guildId, at}` в памяти теста, **без**
сброса бейджей/счётчиков и без изменения дерева. Live: заблокирован до ack-контракта.
RE-вопросы: что считается ack (сервер/канал/сообщение), ответ, коды.

### 3.3 #2 Пригласить на сервер

Gate: `canInvite === true` **и** принятый диалог G-06. Иначе `capability-unknown`/
`not-implemented`, всегда disabled. В G-05 не открывать диалог, не строить URL, не вызывать
list/create. При включении (после G-06): `idle → loading → ready | empty | error` — контракт
G-06, здесь только гейт. 403 — generic; 429 — countdown, кнопка создания disabled; 401 —
auth; timeout — не успех. Fake: **никаких** URL/кодов; проверки копирования — в G-06-тестах
с явной меткой fake. Live: `[RE][L]`.

### 3.4 #3 Заглушить сервер

Gate: read (`muted`, `mute_config`) `[D]`; маршрут `PATCH /users/@me/guilds/{id}/settings`
`[S]`; тело/длительности/область — `[RE]`. Пока disabled. При включении: подменю, выбор
длительности → `pending` → 2xx → отметить текущее состояние; ошибка возвращает прежнее.
`aria-expanded` на пункте; `aria-pressed` нет. 403 — generic, состояние не меняется;
429 — countdown и disabled-выбор; timeout — без оптимистичной мутации. Fake: список
15м/1ч/8ч/24ч `[D]` с меткой fake; полный набор — `[RE]`. Live заблокирован.

### 3.5 #4 Параметры уведомлений

Gate: read (`message_notifications`) `[D]`; маршрут `PATCH …/settings` `[S]`; enum→copy,
набор уровней и тело записи — `[RE]`. Пока disabled, subtitle не рендерится без данных.
При включении: подменю уровней, subtitle = текущий; выбор → `pending` → 2xx → обновить
subtitle и статус; ошибка сохраняет прежний уровень. Закрывается только подменю, не всё
меню. 403 — прежний уровень + generic; 429 — countdown, выбор disabled; 401 — auth.
Fake: «Все сообщения»/«Только @упоминания»/«Ничего» `[D]` в памяти, метка fake; live
заблокирован.

### 3.6 #5 Скрыть заглушённые каналы

Gate: read (`hide_muted_channels`, `channel_overrides[].muted`) `[D]`; запись и
синхронизация `[RE]` (каталог: «на всех ваших устройствах» `[D]`). Пока disabled.
Локальный fake допустим только в тестах; паритетом не является. При включении:
`menuitemcheckbox`, `aria-checked` и фильтрация дерева меняются вместе; гильдия/рейл/
серверное состояние не мутируются. 403/429 — только если появится sync (403 — откат и
generic; 429 — сохранить старое значение + countdown). Локальная операция сама по себе
403/429 не порождает. RE: формат хранения, область (гильдия/аккаунт), sync.

### 3.7 #6 Настройки конфиденциальности

Gate: поверхность/поля/маршрут `[RE]`. Пока disabled; **не** открывать выдуманную модалку.
Если для визуального QA нужна оболочка — только пустая, с явной меткой fake и без полей;
в прод не попадает `[A]`. 403 — generic, диалог открыт; 429 — значения не меняются,
countdown; 401 — auth; timeout — не успех. Live заблокирован.

### 3.8 #7 Редактировать личный профиль; #8 Переместить...

результат неизвестен.

#8: список целей (папки/позиции), порядок и семантика `[RE]`. Пока disabled. Fake:

### 3.9 #9 Покинуть сервер (активен)

Owner disabled `[D]`; confirm `alertdialog`; `pending` блокирует Esc/клик-вне/повтор;
2xx → удалить плитку, выбрать предыдущую/ЛС, `#server-status` «Вы покинули сервер» `[D]`.
Ошибки — по машинному `kind`, без разбора тела: `unauthorized` → «Сессия истекла…» +
auth-gate; `forbidden` → «Недостаточно прав, чтобы покинуть сервер.»; `notFound` →

### 4.3 Позиционирование, overflow, scroll

1. Позиция считается **до** первого paint: снять `hidden`, измерить `offsetHeight`,
   выставить `left/top` в том же кадре. `position:fixed` — меню не расширяет рейл и не
   обрезает тень. В DOM-шиме layout не моделируется (§7.4) — это требование окна.
2. Кламп по обеим осям, 8 px зазор:
   `left ∈ [8, innerWidth − W − 8]`, `top ∈ [8, innerHeight − H − 8]`.
3. **Горизонтальный flip:** если `rect.right + 8 + W > innerWidth − 8`, поставить меню
   слева от opener: `left = clamp(rect.left − W − 8, 8, innerWidth − W − 8)`. Сейчас
   `placeMenu` только сдвигает влево и может наехать на opener/выйти за край.
4. **Вертикаль:** предпочтительно `top = rect.top + rect.height/2 − 24`; если
   `top + H > innerHeight − 8` → `top = innerHeight − H − 8`; если `top < 8` → `8`.
   H берётся из измерения, при `H === 0` (шим/скрыто) — консервативные 480.
   Отдельный «flip вверх» не требуется: `max-height` гарантирует `H ≤ innerHeight − 16`,
   нижний кламп эквивалентен перевороту. Иное — решение PM.
5. `width: min(288px, calc(100vw − 16px))` — при узком окне меню не уезжает за правый край.
6. `max-height: min(480px, calc(100vh − 16px))`, `overflow-y:auto`; прокручивается меню,
   не страница; сфокусированный пункт прокручивается в видимую область
   (`scrollIntoView({block:"nearest"})` или эквивалент) `[A]`.
7. Anchor D1 не подтверждён: решение PM — оставить opener «…» (текущее) или добавить
   контекстное открытие по плитке/правому клику для паритета `[A]`. От этого зависят
   anchor и возврат фокуса (§8 Q1).

| Клик по пункту | не должен одновременно срабатывать как «клик вне» | `[F]` | ✓ |
| disabled-пункт | `aria-disabled`, причина, no-op, не в roving | `[A]` | ✗ (D1/D6) |

**Esc — единый обработчик (обязательное решение rev. 4).** Меню-локальная ветка
(`actions.js:736-740`) обрабатывает Esc без `stopPropagation`, и тот же `keydown` доходит
до `body` (`908-970`), где `menuOpen` уже `false` → `closeTopLayer()` → `switchScreen("chat")`.
Требование: **один** обработчик Esc в `body` (он уже стоит в правильном приоритете:
`menuOpen` → `join` → `leave` → `search` → auth-gate → экран). Меню-локальную ветку
удалить; `stopPropagation()` как альтернатива допустим, но тогда проверка только в окне.
Единый обработчик даёт офлайн-тест: `key(app,"Escape")` при открытом меню на экране
«Настройки» → меню закрыто, фокус на opener, `data-active-screen` = `settings`.

**Tab.** В том же `body`-обработчике **до** `trapTab`: если `menuOpen` → закрыть меню,
сфокусировать opener, `return` без `preventDefault` — браузер продолжит tab-порядок от
opener. Меню не modal: удерживать в нём фокус нельзя.

**Клик вне.** Правило: если `event.target` — фокусируемый контрол (`button`, `a[href]`,
`input`, `select`, `textarea`, `[tabindex]`) или находится внутри него — `closeMenu(false)`,
фокус не трогать; иначе (фон, `body`, текст) — `closeMenu(true)`. Возврат фокуса при
активации пункта и при закрытии по Esc остаётся всегда.

При открытии диалога из меню меню закрывается; после закрытия диалога фокус возвращается
на opener «…» (текущее), а не на пункт меню `[A]`. Возврат на пункт требует переоткрытия
меню — отдельное решение PM, текущий код так не делает.

### 4.5 Диалог/confirm

`alertdialog` (leave), `z=200`, `aria-modal="true"`, `aria-labelledby`/`aria-describedby`,
фокус по умолчанию на «Отмена», Tab зациклен внутри, Esc/клик-вне закрывают только в
`idle`/`error`, в `pending` — блокируются; повторный submit игнорируется. Успех — только
2xx: закрыть, обновить рейл, `role=status`; ошибка — диалог открыт, правки/плитка сохранены.
Reduced motion убирает переходы, не меняя размеры.

**D5, геометрия:** `.dialog` без `max-height`/`overflow` — при окне ниже ~560 CSS карточка
join обрезается, кнопки недоступны. Требование: `max-height: calc(100vh - 48px)`
(= 24 сверху + 24 снизу, `--space-8` — padding backdrop), `overflow-y:auto` на карточке,
`overflow-y:auto` на `.dialog-backdrop` (страховка для очень узких/низких окон), фокус
скроллит к активному полю. Ширина уже `min(--modal-w-sm 442, 100vw − 48)` — не менять.
Фон под `aria-modal` не помечается `aria-hidden`/`inert` — Tab трапится, но AT может выйти
за карточку: требование к G2 либо письменно принятый риск PM `[A]`.
