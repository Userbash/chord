# G3-INVITES-MODALS-SPEC — независимое ревью спецификации

**Вердикт: RETURN (P1).** Спецификация пока не может быть заморожена как единый контракт: в ней есть прямые расхождения с `RE-DEEP-REA.md` и собственным token-only правилом.

## Findings

1. **P1 — REST-контракт принятия неполный.** Спецификация задаёт тело только `session_id` и `invite_instance_id` (`INVITES-SPEC.md:287-290`), но RE §4.1 требует также условный `received_installation_id` и контекст `invite_guild_scheduled_event_id` (`RE-DEEP-REA.md:394-402`). Реализация по этой спецификации потеряет валидные installation/event flows.

2. **P1 — resolve query неполный.** В спецификации указаны только `with_counts` и `with_expiration` (`INVITES-SPEC.md:264-266`), тогда как оракул требует `guild_scheduled_event_id`, `target_channel_id`, `target_message_id`, `with_permissions`, а также условные `with_games` и `with_guild_experiments` (`RE-DEEP-REA.md:427-432`).

3. **P1 — заявленное `flags`/`IS_GUEST_INVITE` не подтверждено оракулом.** `flags` добавлен в request/response и UI (`INVITES-SPEC.md:46-78`, `:181-187`), но RE §4.3 schema перечисляет `max_age`, `max_uses`, `temporary`, `unique` и target-поля без `flags` (`RE-DEEP-REA.md:447-455`). Нужна отдельная доказательная пометка/решение, либо удаление поля из `[D]` контракта.

4. **P1 — нарушение token-only правила внутри самой спецификации.** §0 требует только `var(--token)` (`INVITES-SPEC.md:25-26`), но CSS-пример содержит raw `rgb(0 0 0 / 72%)` (`:383-395`) и raw `48px` в viewport calculations (`:401-409`). Это также делает T-INV-10 (`:872-873`) невыполнимым для приведённого примера.

5. **P2 — TTL matrix противоречит числу вариантов.** §1.2 говорит «8 вариантов», но перечисляет 7 значений (`INVITES-SPEC.md:57-64`), HTML тоже содержит 7 `<option>` (`:143-155`), а T-INV-02 требует ровно 8 (`:864-866`). Нужно определить восьмое значение или исправить count во всех местах.

6. **P2 — неполная error matrix.** Карточка перечисляет только 10006/40007/30001 (`INVITES-SPEC.md:287-290`), тогда как RE §4.1 также фиксирует 10004, 10007, 50035 и возрастные ограничения (`RE-DEEP-REA.md:408-421`).

## Итог проверки

Внешние ассеты и общая a11y-структура описаны последовательно, но перечисленные P1 расхождения должны быть разрешены до передачи G2/G1. Это review спецификации; продуктовый код и Cargo не запускались и не изменялись.
