### 0.2 Чего в дампе нет (честные дыры)

1. **Экрана Go Live в дампе нет.** Ни одного PNG/HTML с превью стрима, панелью «Настройки стрима»,
   тайлами зрителя или полноэкранным режимом. Есть только кнопка «Продемонстрируйте свой экран»
   в панели и строки в настройках.
2. **Пикера источника нет.** Ни скриншота, ни HTML системного диалога, ни списка окон/мониторов.
3. **Тайла зрителя и полноэкранного режима нет.** `voiceChannelEffectsContainer` 833×469 пуст.
4. **Счётчика зрителей нет** — ни строки, ни бейджа на экране.
5. **Меню качества нет** — только строки `Качество передачи*` в каталоге i18n.
6. **Камера не включалась**: `active:false`; ни превью, ни «Камера включена» на экране (только
   как *звук* в звуковой панели).
7. **`STREAM_CREATE/UPDATE/DELETE/SERVER_UPDATE` живьём не приходили** — только по коду клиента.
8. **Запроса старта стрима не видели**: какие именно REST/шлюз-вызовы инициируют `STREAM_CREATE`,
   не установлено (известны только `POST /streams/{key}/notify`, `PATCH /streams/{key}/stream`).
9. **Системного звука нет**: только строки фич; на Linux loopback помечен win32-only.
10. **Ошибок захвата на экране нет** — только строки каталога (`Нет разрешения на показ экрана` и др.).

## 1. Источник истины и разделение ответственности

| Слой | Источник | Статус | Что запрещено |
|-|-|-|-|
| Наличие стрима у участника | gateway `VOICE_STATE_UPDATE` (`self_stream`, `self_video`) | `[S]` (тело `PATCH /guilds/{id}/voice-states/@me` содержит оба поля); live не наблюдался | выводить «стримит» из иконки/активности/списка |
| Жизненный цикл стрима | gateway `STREAM_CREATE` → `STREAM_SERVER_UPDATE` → `STREAM_UPDATE` → `STREAM_DELETE` | `[S]`; live — 0 событий | включать «live» по клику, а не по событию |
| Транспорт стрима | **отдельное** RTC-подключение: `STREAM_SERVER_UPDATE{stream_key, endpoint, token}`; **криптографический блокер B-08** (схема KDF/nonce/AAD и 14-байтная соль media stream, `NETWORK-CONTRACTS.md:473` / `G5-PREREQ.md` C-05: без независимого восстановления схемы ключ из op4 не применим к wire-кадрам) | `[S]`/`[A]` | переиспользовать голосовой endpoint/токен; утверждать о wire-совместимости до снятия B-08 |
| Параметры качества | `streams[].quality`/`rid` из op0/op2 + `remoteSinkWants*`/`maxResolution`/`maxBitrate` из движка | `[L]`/`[S]` | хардкодить «720p/1080p/4K» как список Discord |
| Источник захвата | системный пикер (`presentNativeScreenSharePicker` на Wayland) либо наш путь (portal/X11) | `[D]`/`[S]`; X11-путь `[A]` | перечислять окна/заголовки самостоятельно без явного действия |
| Камера | `getVideoInputDevices`/`setVideoInputDevice` + `self_video` в op4 | `[D]`/`[S]`; live нет | открывать `getUserMedia` в рендерере |
| Stream key | `guild:<guild>:<channel>:<user>` | `[L]` | показывать/логировать ключ и токен |
| Просмотр чужого стрима | события + отдельный RTC + декод (wire-путь зрителя блокирован **B-08**) | `[A]` (полностью) | обещать «зритель работает» до live |

Кто что делает (важно для N3-07/N3-10):

| Слой | Ответственность | Не делает |
|-|-|-|
| G2 UI | DOM, состояния, consent-диалоги, превью-плейсхолдер, тайлы, fullscreen, a11y | не зовёт `getDisplayMedia`, не строит stream key, не открывает WS |
| G1 Core/Network | `/streams/*` REST, `STREAM_*`, второе RTC-подключение, rid/quality, RTP | не рисует и не решает «спросить ли пользователя» |
| G5 Platform | захват (portal/PipeWire/X11/v4l2), энкод (vaapi/rav1e), системный звук | не решает продуктовые состояния |
| G4 QA/Security | тесты «нет захвата без клика», отсутствие ключей в логах | не ослабляет политику ради зелёного |

Правило: UI вызывает **сервис** (`stream.pickSource()`, `stream.start(opts)`, `stream.stop()`,
`stream.setQuality('auto'|'source')`, `camera.preview()`, `camera.enable()`, `camera.disable()`)
и рисует состояние. UI **никогда** не формирует `stream_key`, `token`, `endpoint`, `ssrc`, `rid`.

## 2. Поток Go Live

### 2.1 Машина состояний

`data-stream` на `#voice-panel` — единственный источник стилей кнопки «Продемонстрируйте свой экран»;
`data-view` на `#stream-stage` — видимость сцены.

| `data-stream` | Что видно | Кнопка экрана | Переход | Метка |
|-|-|-|-|-|
| `off` | ничего | `aria-pressed="false"`, активна | клик → `picking` | `[A]` |
| `picking` | ничего (системный диалог поверх) | `aria-pressed="false"`, `aria-busy="true"` | выбор источника → `preview`; отмена → `off` | `[A]` |
| `preview` | `#stream-setup` (превью + качество + звук + «Начать стрим») | `aria-pressed="false"`, активна | «Начать стрим» → `starting`; «Отмена»/Esc → `off` | `[A]` |
| `starting` | `#stream-setup` с `aria-busy="true"`, кнопка disabled | `aria-busy="true"` | сервис `onStreamLive` → `live`; ошибка → `error`; 15 с → `error` | `[A]` |
| `live` | `#stream-live` (таймер, зрители, «Прекратить стрим») | `aria-pressed="true"` + красная точка | `STREAM_UPDATE{paused:true}` → `paused`; stop → `stopping` | `[A]` |
| `paused` | `#stream-live` + строка «Стрим приостановлен» | `aria-pressed="true"` | `paused:false` → `live`; stop → `stopping` | `[A]` |
| `stopping` | «Остановка…», кнопки disabled | `aria-busy="true"` | `STREAM_DELETE` → `off`; 10 с → `error` | `[A]` |
| `error` | `#stream-error` (`role="alert"`) + «Повторить»/«Закрыть» | `aria-pressed="false"` | retry → `picking`; close → `off` | `[A]` |

Правила: (1) `live` ставится **только** по событию сервиса, а не по клику (как `leave` в `VOICE.md`
§2.8); (2) `off` после stop — только по `STREAM_DELETE`, иначе `error` («Остановка не подтверждена»);
(3) одновременный второй клик в `picking/starting/stopping` игнорируется (idempotent).

### 2.2 Consent

| Шаг | Кто спрашивает | Что происходит | Метка |
|-|-|-|-|
| 1 | пользователь | клик по «Продемонстрируйте свой экран» — единственный вход в захват | `[A]` |
| 2 | ОС (портал/композитор) | системный диалог «что показать» + индикатор записи экрана | `[D]` (`sbbPhW`, `ie1mgY`) |
| 3 | Discord/канал | право «Показывать экран» (наша трактовка строки права); без него — `Нет разрешения на показ экрана` | `[D]` строки + `[A]` трактовка (`/x4knx`, `PpfzUE`, `RY8rIc`) |
| 4 | мы | лист `#stream-setup`: превью + качество + «Начать стрим»; до нажатия кадры **никуда** не уходят | `[A]` |
| 5 | ОС | прекращение шаринга пользователем в системном UI → `STREAM_DELETE`/`unavailable` → `off` | `[A]` |

Инварианты (нарушение = блокирующий дефект):

1. **Нет захвата при монтировании** панели, при входе в канал, при открытии настроек.
2. **Нет захвата без явного действия**: только клик по кнопке экрана/камеры.
3. **Нет второго согласия-«галочки», которая что-то запоминает**: разрешение живёт в ОС и в правах
   канала; мы не пишем «больше не спрашивать».
4. **Индикатор всегда виден**, пока идёт захват: `data-stream="live|paused"` + точка `--danger` +
   текст: свой стрим — «Вы стримите!» (`XvBdeT`), чужой — «Смотрит стрим» (`JH1SJ+`); при `paused` —
   отдельная строка «Стрим приостановлен» (`5q17w5`).
5. **Стоп доступен всегда**: `Esc` не убивает стрим молча, но `#stream-stop` доступен из любого
   состояния `live/paused` (в т.ч. клавиатурой).
6. **Никакой записи**: `saveClipEx`, `setClipsRecordingEnabled`, `startLocalAudioRecording`,
   `startRecordingRawSamples`, `setAecDump`, `saveScreenshot` не вызываются (`[D]` имена, `[A]` запрет).
7. **Ключи не в UI**: `stream_key`, `token`, `endpoint`, `secret_key` не рендерятся, не логируются,
   не попадают в `title`/`aria-label`.
8. **Зритель не грузит чужие превью** в списке участников (см. D-02, §4.6).

**Разрешение расхождения (F-04):**
В оригинальном дампе Discord панель имеет ширину 363px, где 4 кнопки занимают ряд высотой 32px с gap 8px и padding 8px.
Однако в нашей архитектуре ширина колонки зафиксирована как **240px** (D-01, SPEC §5.1, `layout-tree-w: 240px`).
При ширине 240px 4 кнопки шириной 80px с gap 8 физически не помещаются в одну строку.
Поэтому в фактическом файле стилей `rust/gui-spike/ui/components/voice.css` закреплена **адаптированная геометрия**:
- Высота кнопок действий `.voice-action` / `.voice-status-actions button`: **28px** (`var(--btn-height-sm)`) вместо 32px;
- Зазор (gap): **2px** (`var(--space-1)`) вместо 8px;
- Padding кнопок: `0 var(--space-2)` (**4px**) вместо 8px;
- Padding панели: `var(--space-2) var(--space-4)` (**4px 8px**);
- Радиус: `var(--radius-xs)` (**4px**) для компактных кнопок 28px.
Реализация UI для панели следует фактическим значениям **28 / 2 / 4** из `voice.css`. Если для экранов Go Live потребуется отдельный крупный ряд действий вне узкой панели (например, в модалке или на сцене), там используются базовые токены 32 / 8 / 8 (`--btn-height` и `--space-4`).

## 11. Что нельзя

1. **Не выдавать `[M]`/`[A]` за паритет.** Экранов стрима в дампе нет — паритет не заявлен.
2. **Не выдумывать px.** Любое число — `[T]`, `[M]`, `[D]`-прямоугольник или `[A]` + `unmeasured`.
3. **Не хардкодить 720p/2.5 Мбит/20 fps** — это наблюдение одной машины, не контракт.
4. **Не строить `stream_key`/`token`/`endpoint`/`ssrc` в UI** — только сервис.
5. **Не включать захват** без явного клика; не открывать `getUserMedia`/`getDisplayMedia`.
6. **Не писать «зритель работает»** до live с двумя клиентами.
7. **Не включать запись, клипы, скриншоты, AEC-дамп, loopback.**
8. **Не перечислять окна/заголовки** и не показывать чужие превью без действия.
9. **Не обещать превью окон на Linux** (`screen_previews` win32-only).
10. **Не менять общие файлы** (`index.html`, `actions.js`, CSS, `tokens.css`) — зона G2/интеграции.
11. **Не копировать ассеты** — ни PNG, ни иконок, ни шрифтов; иконки — свои inline-SVG.
