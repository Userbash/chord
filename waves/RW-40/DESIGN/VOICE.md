### 0.2 Чего в дампе нет (честные дыры)

1. Скриншота/HTML попапа выбора устройства (шеврон «Настройки ввода/вывода») нет.
2. Скриншота состояний `loading / error / no-permission / reconnecting` нет — есть только строки.
3. Индикатора речи (`speaking`) и/или рамки вокруг аватара нет — канал был пуст.
4. Keybind PTT, его редактор и «Режим рации (ограниченный)» на экране не видны.
5. Payload `setDeviceChangeCallback` (hot-plug) не снят — известно только имя API.
6. Источник числа `93 ms` (RTC-статистика? RTCP? отдельный heartbeat?) не установлен.
7. Истории reconnect (сколько попыток, таймауты, backoff) нет: живых обрывов не было.

## 1. Источник истины

| Слой | Источник | Статус | Что запрещено |
|-|-|-|-|
| Состав канала (кто в голосе) | gateway `VOICE_STATE_UPDATE` (+ `VOICE_STATE_UPDATE.channel_id = null` при выходе) | `[S]`; live не наблюдался в 4 capture | вычислять «кто где» по списку участников |
| Join/leave (голос) | gateway **op4** `VOICE_STATE_UPDATE` (`guild_id, channel_id, self_mute, self_deaf, self_video, flags`) + ожидание `VOICE_SERVER_UPDATE{token, guild_id, endpoint}` | `[S]` (`NETWORK-CONTRACTS` §1 п.16); live-окно обязательно | собирать RTC-endpoint в UI, открывать WS из рендерера |
| RTC-сессия | `wss://c-<region>-<hash>.discord.media:<port>/`, op0→op1→op2→op4→медиа | `[L]` (3 сессии) | выбирать регион/хост в UI |
| Речь участника | RTC **op5** `{user_id, ssrc, speaking}` (bool или число) | `[S]`; live не наблюдался | выводить «говорит» из громкости, из JS-анимации или из `setEmitVADLevel` |
| Своя речь/VAD | `setEmitVADLevel`, `setEmitVADLevel2`, `setNoInputCallback` встроенного модуля | `[D]` (имена) | считать, что порог VAD = порог UI |
| Ping | **источник не установлен** (гипотезы: RTC-статистика/RTCP SR-RR; gateway heartbeat 13 750 мс слишком груб для 63…92 мс) | `[A]` | придумывать формулу ping или «потерь» |
| Устройства ввода/вывода | `getInputDevices()/getOutputDevices()` модуля; выбор — `setInputDevice/setOutputDevice` | `[D]` (имена), схема ответа `[A]` | перечислять устройства `navigator.mediaDevices` в обход модуля |
| Hot-plug | `setDeviceChangeCallback` + тумблер «Предложение аудиоустройств» | `[D]` | опрашивать `enumerateDevices` по таймеру |
| Громкость | `setInputVolume/setOutputVolume`, `setVolumeChangeCallback` | `[D]` | хранить громкость в UI как истину |
| Настройки пользователя | локальный store (в спайке — память, `[F]`/`[A]`); серверная персистентность — `settings-proto` (`[L]`, вне этой карточки) | `[A]` | обещать синхронизацию настроек |

Правило: UI вызывает **сервис** (`voice.join(channelId)`, `voice.leave()`, `voice.setSelfMute(bool)`,
`voice.devices.list()`, `voice.devices.select(...)`), рисует состояние и **никогда** не строит
endpoint, токен, ssrc или RTP.

### 2.3 Speaking

**Замер: отсутствует.** Ни одного кадра op5 в трёх сессиях, в канале был один участник,
анимации речи нет ни на одном скриншоте.

Контракт `[A]` (не паритет):

| Свойство | Значение | Метка |
|-|-|-|
| Источник | op5 `speaking` (bool или число) | `[S]` |
| Атрибут | `data-speaking="true|false"` на `.voice-user` | `[A]` |
| Визуал | кольцо 2px `--positive` вокруг аватара 32 (`--avatar-md`), без анимации масштаба | `[A]` |
| Длительность | затухание 120 мс (`--motion-fast`), при `prefers-reduced-motion` — 0 | `[T]`/`[A]` |
| Порог | UI не считает сам: приходит готовый `speaking`; числовой вариант (`0..1`) считать «говорит» при `> 0` — единственное наше правило | `[A]` |
| Доступность | состояние не только цветом: `aria-label` строки получает «говорит» / «микрофон отключён» | `[A]` |

Кольцо 2px (`[A]`, размер взят из `--focus-ring-width` = 2px `[T]`) — цвет `--positive`
(контраст на `--surface-1` = **4.84**, §4.7). Дизайн-ревью: это единственное место, где
`--positive` используется как non-text индикатор ≥3:1 — проходит.

Контракт:

1. `data-self-mute="true|false"`, `data-self-deaf="true|false"` на `#voice-panel` — дублируют
   `aria-checked` (`[A]`).
2. Серверный mute сильнее локального: при `server_mute` кнопка микрофона `aria-disabled="true"`,

3. Deafen не выключает `aria-checked` микрофона: это два независимых флага
   (`self_mute`, `self_deaf` в op4 `[S]`).
4. Никакого «оптимистичного» переключения без подтверждения: рисуем из состояния store,
   store обновляется после op4/`VOICE_STATE_UPDATE` (`[A]` — денежная ставка на паритет с
   оригиналом не подтверждена; в дампе видно только итоговое состояние).

## 5. Consent и приватность

### 5.1 Инварианты (нарушение = блокирующий дефект)

1. **Только свой микрофон.** Ни один API не даёт слушать чужой микрофон; `speaking` — это
   gateway-факт (op5) `[S]`, а не аудиопоток.
2. **Нет скрытого захвата.** Перечисление устройств и открытие аудиопотока — только по явному
   действию (клик по шеврону / «Проверка микрофона») `[A]`.
3. **Нет автозаписи.** Запись собственного звука (`startRecordingRawSamples`,
   `startLocalAudioRecording`, `setAecDump`, `setLoopback`) в UI не вызывается `[D]`+`[A]`.
4. **Нет захвата экрана по умолчанию.** `getScreenPreviews`/`getWindowPreviews` — только после
   явного выбора источника в пикере (`S-02`, вне MVP) `[D]`+`[A]`.
5. **Индикатор.** Пока микрофон активен — в панели видно состояние (не только цветом: `aria-label`);
   при `self_mute=true` кнопка в mute-виде `[D]`/`[A]`.
6. **Данные устройств — PII.** Имена устройств («Система: Easy Effects Source» — реальные имена ОС)
   не логируются и не уходят в аналитику; в логах допустим только тип (`input/output`) `[A]`.
7. **Права проверяет backend.** Нет права — `no-permission`, ноль запросов на медиа `[A]`.
8. **Никаких чужих данных.** Панель показывает только `id`, `display_name`, `mute/deaf/speaking`
   из события; аватар — из локального кэша, не скачивается `[A]`.

### 5.2 Что говорит дамп о захвате (для G4)

| API встроенного модуля | Что делает | Метка |
|-|-|-|
| `getInputDevices` / `setInputDevice` | перечисление/выбор входа | `[D]` |
| `startLocalAudioRecording` / `stopLocalAudioRecording` | локальная запись | `[D]` |
| `startRecordingRawSamples` / `stopRecordingRawSamples` | сырые сэмплы (диагностика) | `[D]` |
| `setAecDump` | дамп AEC (эхо-подавление) | `[D]` |
| `setLoopback` | локальная петля | `[D]` |
| `getScreenPreviews` / `getWindowPreviews` / `presentNativeScreenSharePicker` | превью экрана/окон, нативный пикер | `[D]` |
| `addDirectVideoOutputSink` / `removeDirectVideoOutputSink` | прямой видеосинк | `[D]` |
| `setEmitVADLevel` / `setEmitVADLevel2` | уровень своей речи для индикатора | `[D]` |

для нас перечисленные API — запрещённая поверхность, а не «фича для паритета» `[A]`.

### 5.3 Запрещено

- Инициировать `getUserMedia`/`getDisplayMedia` из панели или при монтировании.
- Считать «говорит» по громкости своего микрофона и применять к чужим строкам.
- Хранить/логировать имена устройств, `session_id`, RTC `token`, `secret_key`.
- Показывать «участник говорит» без op5 (иначе это ложь и утечка ожиданий).
- Включать диагностическую запись/логи по умолчанию.

## 9. Живое против фейка

### 9.1 Что блокирует live

| Блокер | Что именно | Почему нельзя на фейке | Метка |
|-|-|-|-|
| **endpoint** | RTC-хост приходит только в `VOICE_SERVER_UPDATE{token, guild_id, endpoint}` после gateway **op4** `VOICE_STATE_UPDATE` | нужен живой логин + вход в канал; без него нет `wss://c-<region>-…discord.media` | `[S]` |
| **RTC op4** | `Session Description` содержит `secret_key` (32 Б) — в дампах **вырезан** | без ключа нельзя проверить шифрование/дешифровку SRTP; `VOICE-CRYPTO.md` утерян | `[L]`/`[A]` |
| **UDP** | медиа-сервер `IP:port` из op2 + discovery | без live нет ssrc/порта; локальный UDP-мок не докажет совместимость | `[L]` |
| **speaking** | op5 не наблюдался (в канале был один человек) | нужен второй клиент/участник с согласия | `[S]`/`[A]` |
| **RTCP-статистика** | тела `SR`/`RR` шифрованы (tag 16) | потери/джиттер снаружи не читаются; ping-источник не установлен | `[L]`/`[A]` |
| **hot-plug** | payload `setDeviceChangeCallback` не снят | нужен живой модуль + физическое устройство | `[D]`/`[A]` |
| **PTT keybind** | значение клавиши не снято | нужен живой «Режим рации» + редактор | `[A]` |
| **reconnect** | обрывов не было | нужен живой разрыв сети/смена региона | `[A]` |

Дополнительно: окно, сеть, `cargo` и коммиты в этой карточке **запрещены** — live-проверки
не выполнялись.

### 9.2 Что можно и нужно делать на фейке

1. Вся панель и все 12 состояний §2.7 — по фейковому `voice`-store.
2. Участники/`speaking`/mute — по событиям фейка (включая числовой `speaking`).
3. Ping-значения и `data-quality` — из фейка; формат `93 ms` и `visually-hidden`.
4. Попап устройств, выбор, hot-plug, `device-missing` — фейковый `devices`.
5. PTT: `keydown`/`keyup`, `held`/`blocked`, «нет клавиши» — без ОС.
6. Join/leave/reconnect-таймауты — фейковые часы.
7. Все a11y-инварианты §8.5 и приватность §8.6.
8. Экран настроек: голосовые строки как подмножество (не трогая 38 `[F]`).

- «Speaking как в Discord» — анимация не наблюдалась.

- «38 = паритет» — числа совпали случайно (§3.5).
