# Review: G3-VOICE-DEVICES-SETTINGS-SPEC

Вердикт: **RETURN** (P0: 0, P1: 1, P2: 2)

Проверена `VOICE-DEVICES-SETTINGS-SPEC.md` против `rust/crates/discord-voice/src/devices.rs`, `VOICE.md`, `voice-spec.json` и `rust/gui-spike/ui/tokens.css`. `cargo` не запускался; продуктовый код и тесты не изменялись.

## Замечания

### P1 — конфликт hot-plug fallback с дизайн-контрактом

В спецификации §3.2, строки 361–363, при исчезновении выбранного устройства предписано автоматически выбирать системное default или первое доступное, а при отсутствии устройств устанавливать `aria-disabled`. Это соответствует реализации `VoiceDevicesState::update_device_list` (`devices.rs:288–338`), но прямо противоречит `VOICE.md` §3.2: событие hot-plug обновляет список и **не переключает устройство само**, переключение только по явному клику; исчезновение входа отражается `device-missing`/`MA+OZh`, разговор не рвётся. `voice-spec.json` также фиксирует `devices.hotplug.autoswitch: false` и payload события как unknown. Нужна согласованная трактовка источников и один контракт для UI: либо fallback модели явно не является фактическим выбором аудиоустройства до подтверждения, либо принять новое решение вместо текущего `VOICE.md`/JSON-контракта. В текущем виде потребитель получает взаимоисключающие требования.

### P2 — VAD UI расходится с оракулом чувствительности

В §1.2/§3.4 специфицирован собственный слайдер `vadThresholdDb` с диапазоном `-128..=127` дБ и отдельным `DEFAULT_VAD_THRESHOLD_DB`. Реализация `devices.rs` действительно имеет `VoiceActivity { threshold_db: i8 }`, но `VOICE.md` §3.4 и `voice-spec.json` `devices.sensitivity.slider` описывают UI как чувствительность `0..100` (в дампе 26.109…), авто-чувствительность и API `setNoInputThreshold`. В спецификации автоматический режим упомянут лишь как отключающий ручной db-порог; не определено отображение/преобразование имеющейся шкалы UI `0..100` к порогу Rust и не указано, что db-слайдер является отдельным непаритетным контролом. Уточнить модель и явно маркировать authored adaptation, иначе нельзя подтвердить соответствие UI оракулу.

### P2 — неполные имена доступности для групп и состояния PTT

§2.2 задаёт `aria-label` на `<div>` групп VAD/PTT, но не задаёт им `role`/семантический контейнер; в §5.1 те же контейнеры также перечислены как `div` с именем. На обычном `div` такое имя не гарантирует доступное именованное группирование. Использовать `fieldset`/`legend` либо `role="group"` с `aria-labelledby`/`aria-label`. Кроме того, строка о системной блокировке PTT (`vxfv7v`) присутствует среди источников/VOICE.md, но переход в состояние blocked в спецификации захвата клавиши не определён: нет поведения при потере фокуса/недоступности GlobalShortcuts и доступного сообщения о блокировке.

## Проверки без замечаний

- Оба селекта (input/output), инициализация с `isDefault`, явный выбор и состояния no-device описаны; для обычного сценария это согласуется с `devices.rs`.
- Громкость ввода `0..=100`, вывода `0..=200`, defaults `100%` совпадают с Rust и JSON-слайдерами `OX2Bnr`/`aUJ062`.
- `VoiceActivity`/`PushToTalk`, захват клавиши, задержка PTT `0..=2000` мс и инвариант `effectiveMute = userMute || selfDeaf` покрыты. Диапазон и логика задержки совпадают с Rust; `200` мс дефолт является явной UI-адаптацией, не значением `VoiceDevicesState` (в Rust режим по умолчанию VAD).
- ARIA для селектов, range-контролов, switch, live notice и meter в основном описана; замечание выше касается семантики именованных групп и недостающего blocked-state.
- Все использованные в спецификации `var(--*)` найдены в `tokens.css` (не найдено отсутствующих переменных). Поиск по спецификации не нашёл сырых hex, `rgb()/rgba()` или `hsl()/hsla()` цветовых литералов.

## Ограничения

Ревью статическое и read-only. Проверка токенов охватывала имена переменных в спецификации; `VOICE.md` и JSON содержат измеренные hex-цвета как данные/исторические замеры, но они не включены в CSS-стили этой спецификации.
