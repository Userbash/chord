## 2. Формат сообщения (одно сообщение = один факт)

```
[DATE] [GROUP] [TASK-ID] [TYPE: status|blocker|handoff|review]
WHAT: <1 строка>
EVIDENCE: команда → exit → лог
NEXT: <кто/что/когда>
```

## 3. Handoff между группами

1. Автор пишет `handoff` в канал своей группы + PM.
2. PM проверяет контракт и переносит задачу в доску.
3. Принимающая группа подтверждает вход (файлы/контракт) или возвращает с repro.
4. Без подтверждения задача не считается переданной.

## 4. Синхронизация

- Старт: PM публикует фокус дня в `TASKS.md` §«Текущий фокус».
- Каждые 2 закрытые задачи: чекпоинт в `PROJECT-CONTEXT.md`.
- Блокер: сразу в канал + PM; не ждать конца задачи.
- Спор о контракте: PM + `DECISIONS.md`, не правка чужих файлов.

## 5. Эскалация

| Уровень | Триггер | Действие |
|---|---|---|
| L1 | вопрос внутри группы | lead решает |
| L2 | стык групп | PM + контракт |
| L3 | 2 одинаковых отказа | смена подхода |
| L4 | 3-я попытка/баланс/ToS | владелец |

## 6. Качество коммуникации

- Только факты и команды; «работает» без exit code не принимается.
- Один task-ID на сообщение; не смешивать темы.
- Секреты/токены/пароли в каналах запрещены.
- Решения фиксируются в DECISIONS, а не только в чате.
