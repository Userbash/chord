2. **Ширина сайдбара в захвате = 375**, а не дефолтные 268 из `:root`. Измерение подтверждается CSS-формулой
   и JS-фолбэком 375, но причина (persisted user setting vs. новый дефолт сборки) не аттестована — `assumption`.
3. **Исходящие WS-кадры не сохранены** (только `len`+`sha256`), поэтому op14/op8 payload — `assumption`;
   подтверждён только серверный ответ (`GUILD_MEMBER_LIST_UPDATE` SYNC, `GUILD_MEMBERS_CHUNK`).
4. **`limit>100` не пробовался**, серверный потолок 100 взят из кода клиента (`limit:100`) — `assumption`.
5. **Высоты сообщений выведены из CSS-правил**, а не измерены построчно: прямых rect'ов строк сообщений в
   дампе нет (есть только `msg-rect` контента: 66 = 3×22 и аватар 40 px на скриншоте).
6. **Размер страницы поиска** и **точные padding'и строки канала/composer** — `assumption` (см. `RESEARCH.md` §8).
7. Счётчики READY различаются между снимками (`member_count` 24 227 vs 24 229; 7 гильдий/272 канала в первом,
   83 канала у ITSKIDON во втором) — это разные сессии, оба значения фактические.
8. `ui3/`, `ui5/` содержат только ЛС/попапы и для раскладки каналов не использовались (в `RESEARCH.md` не
   цитируются); `ui4/` пуст.
