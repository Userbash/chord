## 1. Сделано

  - гильдия: обязательный `id`; `unavailable`, `name` (top-level → `properties.name`),

    `version` (десятичная строка → `u64`);
  - каналы: обязательные `id`+`type`; все поля §3.3 (`parent_id`, `position`, `flags`, `nsfw`,
    `topic`, `last_message_id`, `last_pin_timestamp`, `permission_overwrites`,
    `rate_limit_per_user`, `bitrate`, `user_limit`, `rtc_region`, `video_quality_mode`,
    `default_auto_archive_duration`); у overwrite обязателен `id`, `allow`/`deny` — decimal-строки;
  - роли (`permissions` — decimal-строка, `color`/`position`/`flags` — числа), эмодзи
    (`roles: null` → `[]`, элементы-снежинки фильтруются с `ignored`), стикеры
    (`type` → `sticker_type`, `description: nil` → `None`);
  - `null`/атом `nil` — «нет значения» без диагностики; неверный тип необязательного поля —
    дефолт + `diagnostics.ignored` (`guilds[i].channels[j].position`, …);
  - битый элемент (не map, нет/отрицательный/нечисловой `id`, нет `Channel.type`) —
    skip + `diagnostics.malformed` (`guilds[i]`, `guilds[i].channels[j]`, …);
  - дубликаты `guilds`/`channels`/`roles`/`emojis`/`stickers` — last wins, позиция первого
    вхождения, `duplicates` (`guilds:<id>`, `guilds:<gid>.channels:<id>`, …).
- `src/ready/snapshot.rs` — замороженная композиция сохранена (якоря `d`/`d.guilds`/`d.user`/
  `d.session_id`, `parse_user → None ⇒ InvalidId`, делегирование social/read_state, привязка
  `merged_members`, `unknown_top_level`, `raw`). Донастроена диагностика §2.3: неверный тип

  `d.subdivision_code`, `d.friend_suggestion_count`, `d.api_code_version`,

  `d.user_settings_proto`). Отсутствие/`nil` — дефолт без диагностики.
- `tests/ready_core.rs` — 14 тестов A1–A14 на публичном `Ready::parse`/`from_dispatch`.
  Осознанные границы (чтобы набор был зелёным при заглушках соседей):

## 6. Риски / вопросы

1. **A3 `members.len()=1`.** В дизайне A3 указан, но `members` приходит из `merged_members`
   (парсер W12b, на старте W12a — заглушка). Чтобы W12a был зелёным при заглушках, значение
   не утверждается; контракт закрывает B6 (`ready_social.rs`) и привязка в `snapshot.rs`
   (7 групп ↔ 7 гильдий, без `malformed`). Прошу ревьюера подтвердить, что этого достаточно.
2. **Диагностические строки.** `malformed`/`ignored` вложенных полей используют индексы провода
   (`guilds[i].channels[j].position`), `duplicates` — id (`guilds:<gid>.channels:<id>`) — как в
   примерах дизайна §3.3. Строки для top-level скаляров — `d.<key>` (как `d.users` в §3.3).
3. **Новые `ignored` для скаляров.** Добавлены по §2.3 («неверный тип → дефолт + ignored»);
   A‑кейсы их напрямую не проверяют (A2 подтверждает, что на полной фикстуре диагностика пуста).
   Если координатор хочет оставить скаляры «тихими» — правка локальна в `snapshot.rs`.
4. **A8/A2-границы.** Части `users:5 → ignored` и поля `user` кроме `id` не проверяются
   (P-3/W12b); коллекции social/read_state в A2 не утверждаются (заглушки соседей).
5. **§8.** Новый Rust-тест создан, но Rust-тесты вне JS meta-регистра `TDD-PLAN.md` §8, а доки —
   зона координатора (ТЗ §0): строку §8 не добавлял.
6. `gate:worker` не запускался (ТЗ §8.0 — координатор после слияния). Коммитов нет.
