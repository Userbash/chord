## 1. Сделано

`parse_read_state` / `parse_user_guild_settings` — сигнатуры §3.4 не менялись; заглушки заменены
полным разбором C-части контракта A1:

- отсутствие/`nil` → `Default` без диагностики; не-map → `Default` + `ignored`
  (`d.read_state` / `d.user_guild_settings`); `entries` неверного типа → пусто + `ignored`;
- `entries[]` / `channel_overrides[]`: обязательные `id` / `channel_id` через `value::unsigned`;
  битый/отрицательный id → элемент пропущен + `malformed` (`read_state.entries[1]`,
  `user_guild_settings.entries[0].channel_overrides[2]`; §2.3, §3.3 — без `d.`-префикса);
- необязательные поля — `value::integer` / `unsigned` / `boolean` / `text`: `nil` → `None`,
  неверный тип → дефолт + `ignored` с полным путём (`d.read_state.version`,
  `d.read_state.entries[0].flags`, `...channel_overrides[0].mute_config.end_time`);
- `partial`: атом/строка `"true"`/`"false"`, Int `0`/`1`; иное (`"yes"`, `2`) → `false` + `ignored`;
- дубликаты: `read_state.entries:{id}`, `user_guild_settings.entries:{id|nil}` — last wins,
  позиция первого, через общий `value::dedup_last_by`; `channel_overrides` в списке §2.3 нет —
  не дедуплицируются;
- `channel_overrides: null` / `mute_config: "nil"` / `guild_id: "nil"` → пусто/`None`;
- `read_state.entries[].id` не сверяется с каналами: id пользователя/гильдии принимаются (P2-07).

Тесты C1–C11 — только через публичный `Ready::parse`/`from_dispatch`; для синтетики добавлены
якоря `guilds:[]`, `user:{id:"1"}`, `session_id:"s"`. C10 дополнительно покрывает обязательный
`ChannelOverride.channel_id` (то же правило §2.3 «битый id элемента → skip + malformed»).

## 6. Риски / вопросы

1. **Конкурентная волна.** Первый crate-wide прогон (13:43) упал на `ready_social::b01` —
   W12b в этот момент ещё вёл red/green (`social.rs`/`ready_social.rs` обновлены в 13:43–13:44).
   После их фикса весь крейт зелёный; в `w12c-green.log` — только финальный зелёный прогон.
   Финальная перепроверка в 13:46 один раз поймала кратковременный `E0277` при компиляции lib
   (чужая незавершённая правка); немедленный повтор — снова `11 passed; 0 failed`. Если
   координаторский гейт попадёт в чужой red/полузапись — падение будет не из C-части.
2. **Конвенции диагностик** (прошу сверить на ревью с W12a/W12b): `ignored` — полный путь с `d.`
   (пример §3.3 `d.read_state.version`), `malformed`/`duplicates` — от ключа коллекции
   (`read_state.entries[1]`, `read_state.entries:7`, `user_guild_settings.entries:nil`).
3. **`nil` верхнеуровневых `read_state`/`user_guild_settings`** трактуется как отсутствие
   (`Default` без `ignored`) — следствие §2.3 «`nil` ≡ отсутствие»; зафиксировано C9.
4. **Полевые `ignored`** (неверный тип вложенного поля) реализованы по §2.3, но отдельного
   C-кейса в §5.3 нет: C7/C8 проверяют контейнер и `partial`, C10 — обязательные id. Если нужен
   тест на `entries[0].flags:"x"` — это расширение спеки (после red — новый red-лог).
5. C9 зелёный уже на заглушках (дефолтное поведение) — ожидаемо, в red-логе это видно;
   кейс остаётся регрессией.
6. `channel_overrides` не дедуплицируются: в списке last-wins §2.3 их нет. Если нужен dedup по
   `channel_id` — это изменение контракта.
7. **Чужая clippy-правка (снята).** В 13:46 конкурентная правка `tests/rest_client.rs`
   временно давала `clippy::while_let_loop` на `--all-targets`; к 13:47 файл исправлен,
   финальный `--all-targets` → 0. Мои цели (`--lib`, `--test ready_read_state`) были чисты
   и в промежутке.
8. `gate:worker` не запускался (запрещён заданием); cargo-проверки локально зелёные.
