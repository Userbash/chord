# RW-28 — решения TL по итогам независимого ревью

Дата: 2026-10-22. Ревьюер: независимый агент (read-only, свои прогоны и оракулы).
Вердикт: «доработка» — P0 ×1, P1 ×1, P2 ×3, P3-ниты.

## P0-1 — `Auto` и формы ±2

**Находка.** Замороженный §1 TZ требовал спецформы только для −1/0/1, а данные/тест/оракул
содержали ICU-формы для ±2 (`позавчера`, `vorgestern`, `明後日`).

**Решение TL-1.** Источник истины для данных — ICU-оракул Node 24: `Intl.RelativeTimeFormat`
с `numeric: "auto"` действительно отдаёт ±2-формы для `day` в части локалей. Ограничивать
таблицу до −1/0/1 значило бы разойтись с ICU и потерять точность рендера. Поэтому:

- §1 TZ-W28a приведён к ICU: «спецформы, включая локальные −2/+2; при отсутствии — `Always`»;
- тест `t04` переименован в `t04_auto_special_forms_follow_icu` и дополнительно проверяет, что
  для единиц без ±2-данных (`hour`/`minute`/`second`) `Auto` совпадает с `Always`;
- данные не перегенерированы по существу (только шапка `Node %s` → `Node v24.21.0`), оракул
  побайтово тот же.

## P1-1 — точность `i64` > 2^53

**Находка.** `magnitude as f64` терял младшие цифры и мог менять плюральную категорию
(`1000000000000000001` → категория `many` вместо `one`).

**Решение.** Добавлены точные целочисленные пути:

- `plural::plural_category_integer(locale, u64, kind)` — операторы CLDR (`i`, `v`, `f`, `t`,
  `i mod 10/100`, `exact_million`) считаются из `u64` без f64; для `f64`-входа поведение
  не изменилось (общий `select` с операндами);
- `format::format_integer_unsigned(u64, locale)` — группировка по десятичным цифрам;
  `format_integer(i64)` переведён на него (знак + `unsigned_abs`);
- `relative::format_relative` использует оба точных пути; добавлен тест `t12` на
  `9_007_199_254_740_993`, `i64::MAX` и `ru`-категорию `one`.
