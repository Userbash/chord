## 3. Детальные аннотации и инструкции к выполнению каждой задачи

### TASK-825: Инвайты, Captcha и бесшовный fallback авторизации сессии при вступлении на сервер (P0)

#### 3.1. TASK-825.1 (P0 Backend Core) — Fallback в `token_or` на `data::resolve_live_token()`
- **Файл:** `rust/gui-spike/src/main.rs`
- **Проблема:** Если Linux Keyring пуст или недоступен через D-Bus/Secret Service, `token_or` возвращает `MissingToken`, хотя реальный токен активен в `LIVE_SESSION`.
- **Инструкция по решению:**
  1. В функции `token_or` после проверки результата `blocking(load).await`:
     ```rust
     let tok_res = blocking(load).await;
     if let Ok(Ok(Some(token))) = &tok_res {
         if !token.trim().is_empty() {
             return Ok(token.clone());
         }
     }
     if let Some(live_token) = data::resolve_live_token().filter(|t| !t.trim().is_empty()) {
         return Ok(live_token);
     }
     tok_res
         .map_err(|_| storage())?
         .map_err(|_| storage())?
         .ok_or_else(missing)
     ```
  2. Убедиться, что тесты `token_or_preserves_domain_error_codes` остаются зелеными (в тестах `resolve_live_token()` возвращает `None`, поэтому код `MissingToken` сохраняется).
- **Критерий приемки:** Вызов `resolve_invite` и `accept_invite` при наличии живой сессии никогда не падает с `MissingToken`.

#### 3.2. TASK-825.2 (P0 Backend/API) — Публичный доступ к `resolve_invite` (Optional Bearer)
- **Файл:** `rust/gui-spike/src/main.rs`, `rust/crates/discord-core/src/rest/`
- **Проблема:** В Discord REST API v9 эндпоинт `GET /api/v9/invites/{code}?with_counts=true&with_expiration=true` является публичным и не требует авторизации. Сейчас `resolve_invite` жестко требует токен.
- **Инструкция по решению:**
  1. В `resolve_invite` делать чтение токена опциональным:
     ```rust
     let maybe_token = token_or::<InviteError, _>(
         move || backend.token(),
         || InviteError::Storage,
         || InviteError::MissingToken,
     ).await.ok();
     let api = match maybe_token {
         Some(t) => DiscordInvites::new(&t)?,
         None => DiscordInvites::anonymous()?,
     };
     ```
  2. Выполнять `GET /invites/{code}` анонимно, если токен не предоставлен.
- **Критерий приемки:** Анонимный вызов `resolve_invite("eSrxp2YGUC")` возвращает превью сервера (название, иконка, число участников).

#### 3.3. TASK-825.3 (P0 Backend/Net) — Клиентские заголовки `X-Context-Properties` в `accept_invite_with_captcha`
- **Файлы:** `rust/crates/discord-core/src/rest/invites.rs`, `rust/gui-spike/src/invites.rs`
- **Проблема:** Discord отклоняет hCaptcha токен с 401/unauthorized, если запрос отправлен без заголовков клиентского контекста.
- **Инструкция по решению:**
  1. Сверить с эталоном `reference-oracle/rest-d02.md`: Discord при принятии инвайта отправляет:
     - `X-Context-Properties`: base64-encoded JSON `{"location":"Join Guild"}`
     - `Referer`: `https://discord.com/channels/@me`
     - `X-Super-Properties`: свойства клиента Electron/Tauri
  2. Добавить установку данных заголовков в HTTP POST запрос `POST /api/v9/invites/{code}` при передаче капчи.
- **Критерий приемки:** Discord принимает капчу без ошибки `unauthorized`.

#### 3.4. TASK-825.4 (P1 Frontend UI) — Валидация и сохранение инпута инвайта в UI
- **Файл:** `rust/gui-spike/ui/app.js` (модуль `createJoinServer`)
- **Проблема:** При возникновении ошибки текст ссылки в поле ввода очищался или кнопка оставалась заблокированной, заставляя пользователя нажимать несколько раз вхолостую.
- **Инструкция по решению:**
  1. Сохранять значение `join-invite-input` при любых ошибках сети/капчи.
  2. Разблокировать кнопку «Присоединиться» и выводить понятное сообщение об ошибке (например, «Пройдите капчу» или «Ссылка недействительна»).
- **Критерий приемки:** Текст инвайта сохраняется при повторных попытках.
