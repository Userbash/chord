## 1. Выявленные архитектурные дефекты и сбои

### А. 18 мест хардкода фикстурного ID пользователя в `data.rs`
- В [`rust/gui-spike/src/data.rs`](file:///home/sanya/orca/project/rust/gui-spike/src/data.rs) захардкожен ID `384299970632876032`. При входе любого другого аккаунта списки серверов заменяются пустыми массивами или фикстурами.
- **Требование:** Список серверов, каналов и друзей должен быть строго динамическим и определяться ответами Discord API (`/users/@me/*`) для текущего авторизованного пользователя.

### Б. Разрыв синхронизации шлюза и текста в реальном времени
- Отправленные сообщения успешно уходят в Discord REST (`POST /channels/{id}/messages`), но не синхронизируются мгновенно на клиенте через события шлюза `MESSAGE_CREATE`.

### В. Утрата медиа-функций в личных сообщениях (Direct Messages)
- В ЛС отсутствуют кнопки голосового звонка (`CALL_CREATE`), включения камеры, демонстрации экрана («демки» / Go Live) и создания групповых чатов (`#group-dm-dialog`).

### Г. Сбой при попытке удаления чужих сообщений (`delete_message` 403 Forbidden)
- В старой сборке `beta` отсутствовал контроль прав на удаление сообщений:
  - В ЛС (Direct Messages) можно удалять **только свои собственные сообщения**. Удаление чужих сообщений невозможно в силу протокола Discord.
  - На серверах (в гильдиях) удалять чужие сообщения разрешено **только** пользователям с правами `MANAGE_MESSAGES` (`1n << 13n`), `ADMINISTRATOR` или `isOwner`.
  - При попытке удалить чужое сообщение без прав Discord API возвращает HTTP 403 Forbidden, что приводило к сбою/ошибке в интерфейсе.

### CARD-DYN-005 (`P0` / Отдел `G2 Frontend` & `G1 Backend`)
**Защита от сбоя при удалении сообщений и проверка прав (Permissions Guard on `delete_message`):**
- **Файлы:** `rust/gui-spike/ui/features/chat.js`, `message-actions.js`, `rust/gui-spike/ui/app.js`.
- **Правило поведения:**
  1. **В личных сообщениях и групповых чатах (`@me`):** разрешено удалять **только свои собственные сообщения**. Кнопка удаления на чужих сообщениях скрыта.
  2. **На серверах (в гильдиях):** удалять чужие сообщения разрешено **только** при наличии права `MANAGE_MESSAGES` (`1n << 13n`), `ADMINISTRATOR` (`1n << 3n`) или владельца сервера (`isOwner`). На чужих сообщениях при отсутствии прав кнопка удаления скрыта.
  3. **Защита от ошибки:** При любой попытке вызова `delete_message` без прав перехватывать действие до отправки в сеть, предотвращая HTTP 403 Forbidden, и выводить уведомление: *«У вас нет прав на удаление чужого сообщения»*.
