# AGENTS.md — правила агентов в discord-lab

Ты работаешь в репозитории `discord-lab` (локальный CLI: анализ Discord через Frida/CDP).
Перед работой прочитай: `PROCESS.md` (процесс и роли), своё ТЗ, `TASKS.md` (карточка задачи),
`TDD-PLAN.md` (план и контракты), `waves/STATE.md` (журнал волн — где остановились).
`PROCESS.md` — источник истины по процессу.

## Как работать

1. **Strict TDD.** Сначала тест (red), прогони и зафиксируй падение командой. Затем минимальный
   код (green). Без теста продуктовый код не пишется. Тесты сверяют контракт с независимым
   оракулом (реальный артефакт, jq/awk/md5), а не с текущей реализацией.
2. **Только свои файлы** из ТЗ. Множества файлов воркеров не пересекаются. Чужие тесты, чужие
   модули, доки и §8 без разрешения координатора не трогаются.
3. **Гейт перед отчётом:** `npm run gate:worker` должен быть зелёным. Если упал e2e — гейт сам
   делает повтор и сохраняет оба результата; флаки не замалчиваются.
4. **Отчёт** по шаблону PROCESS.md §4.2: сделано, red-прогон, green-прогон, gate, файлы, риски.
   Задача закрывается приёмкой координатора, а не отчётом.
5. **Вопросы** — координатору (оркестрация/ask), не догадки. При неясности ТЗ — остановись и
   спроси.
6. **Журнал волн.** Артефакты волны (ТЗ, red/green-логи, отчёт, копии тестов) сохраняются в
   `waves/<ID>/`; после приёмки координатор дописывает `waves/db.jsonl` (append-only, события
   схемы v1) и обновляет `waves/STATE.md`. Журнал стережёт мета-тест `waves-sync`.

## Запреты

- `logs/`, `functions/`, `evidence/` — golden: **только чтение**. Никаких записей/переименований.
- Никаких `git commit/push` — коммиты делает координатор (уровень L1).
- Никаких сетевых вызовов, установок пакетов и изменений `package.json` без разрешения.
- Не спавнить Discord (`device.spawn`) и не делать attach/walk на живом Discord без окна,
  согласованного координатором.
- Не «зеленить» тесты правкой тестов под код.

## Стиль

- Node ≥ 24, ESM, `// @ts-check` + JSDoc в каждом модуле; `npx tsc -p tsconfig.json` — чисто.
- Сообщения CLI и доки — на русском; коды выхода: 0 успех, 1 ошибка аргументов, 2 среда недоступна.
- Тесты skip-aware: отсутствие внешней среды → skip с причиной, а не падение.
- Ошибки не глотать молча: либо последствие (код/счётчик/сообщение), либо явный комментарий,
  почему это best-effort.
