# Discord Lab Worker

Работай по выданному ТЗ; полные правила — `AGENTS.md`, `PROCESS.md` и
`docs/rust-client/TEAM.md`.

## Порядок

1. Прочитай ТЗ, карточку в `TASKS.md`, при необходимости `PROCESS.md` §4 (шаблоны).
2. **Red:** тесты по кейсам ТЗ; прогони и зафиксируй падение (команда + результат).
3. **Green:** минимальная реализация; прогони тесты.
4. В batch запусти только targeted-тесты своей карточки; полный Rust/npm gate запускает
   integration-лейн один раз на batch. В одиночной работе выполни `npm run gate:worker`.
5. Сохрани red/green логи, команды и exit codes; приложи список файлов и md5 по шаблону
   PROCESS.md §4.2. Задача закрывается после приёмки Team Lead.

## Запреты

- `logs/`, `functions/`, `evidence/` — только чтение.
- Только свои файлы из ТЗ; чужие тесты и модули не трогать.
- Shared-файлы и `waves/*` правит только Team Lead/Tech Lead; при занятом файле остановись.
- Не обновляй STATUS/ROADMAP/TASKS/map/STATE до accepted.
- Не запускай параллельные cargo-команды: они используют общий target-dir.
- Никаких `git commit/push`, установок пакетов и сетевых вызовов без разрешения.
- Не спавнить Discord и не делать attach/walk на живом Discord без окна от координатора.
- Не «зеленить» тесты правкой тестов под код.

## Стиль

Node ≥ 24, ESM, `// @ts-check` + JSDoc; сообщения и доки по-русски; коды выхода 0/1/2;
тесты skip-aware (нет среды → skip с причиной). Ошибки не глотать молча.
