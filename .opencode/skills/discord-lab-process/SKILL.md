# Discord Lab Process

Источник истины — `PROCESS.md` в корне проекта (прочитай его перед крупной работой).
Краткая выжимка:

## Роли

Владелец (пользователь) → координатор (план/ТЗ/приёмка/выпуск) → воркеры (свои файлы, strict TDD)
→ вторая модель (чувствительные изменения). Golden (`logs/`, `functions/`, `evidence/`) — только чтение.

## Волна

1. Карточки в `TASKS.md`: ID, микрозадача, владелец, статус.
2. Матрица непересекающихся файлов + ТЗ воркерам (шаблон PROCESS.md §4.1).
3. Воркер: red-тест → код → `npm run gate:worker` → отчёт (§4.2).
4. Приёмка координатором (§4.3); live/golden/удаления — ещё и вторая модель (§4.4).

## Гейты

- `npm run gate:worker` — typecheck, meta, unit, smoke (быстрый, для воркеров).
- `npm run gate:release` — + e2e (повтор при падении), coverage, golden-сверка.
- `npm run gate:qualify` — + tarball и qualification-файл (sha256); выкладка сверяет
  `node scripts/gate.mjs --verify-qualification <file>`.
- `npm run golden:freeze` — md5-манифест golden-каталогов.

## Нельзя нарушать

- Skip ≠ pass: пропуски фиксируются в warnings гейта.
- Форматы артефактов — обратная совместимость («миграции»): новое чтение читает старые файлы.
- Живые операции (attach/spawn/walk на Discord) — только по согласованию; `--spawn` — вручную.
- Kit руками не правится: любая правка → новая версия и новый `gate:qualify`.
- В выпуск едет только одобренное владельцем; остальное — в backlog `TASKS.md`.
